## 核心技术要点

### 1. 游戏循环机制

**原版Progress Quest**：
- 使用JavaScript Web Worker作为精确定时器
- 每次定时器触发（约1秒），检查任务是否完成
- 如果完成，调用 `Dequeue()` 处理下一个任务

**Python实现**：
- 使用Python `threading.Thread` 实现定时器循环
- 每0.1秒更新一次，提高响应速度
- 使用 `time.time()` 计算精确时间间隔

### 2. 任务系统

**任务格式**：
```
原始格式: "task|时间(毫秒)|描述"
Python格式: Task(type=TaskType.TASK, duration=2000, description="任务描述")
```

**任务类型**：
- `TaskType.TASK`：普通任务
- `TaskType.PLOT`：剧情任务

**任务队列**：
- 使用列表存储待处理任务
- `Q()` 函数添加新任务
- `Dequeue()` 函数处理任务队列

### 3. 进度条系统

**实现要点**：
```python
class ProgressBar:
    def reset(self, new_max: float, new_position: float = 0.0):
        """重置进度条"""
        self.max_value = new_max
        self.current_value = min(new_position, new_max)
    
    def increment(self, amount: float):
        """增加进度"""
        self.current_value = min(self.current_value + amount, self.max_value)
    
    def is_done(self) -> bool:
        """是否完成"""
        return self.current_value >= self.max_value
```

### 4. 时间计算

**升级时间公式**（基于原版）：
```python
def get_exp_to_next_level(self) -> float:
    """获取升级所需经验值（秒）"""
    # 基于原版Progress Quest的公式
    return (20 + (1.15 ** self.level)) * 60
```

**任务时间计算**：
- 普通任务：1-5秒
- 剧情任务：1秒

## 技术难点和解决方案

### 难点1：精确计时

**问题**：Python的 `time.sleep()` 不够精确，可能影响游戏节奏。

**解决方案**：
- 使用 `time.time()` 计算精确时间间隔
- 限制elapsed范围，避免时间跳跃
- 使用线程实现独立的定时器循环

### 难点2：UI更新性能

**问题**：频繁更新UI可能导致界面卡顿。

**解决方案**：
- 使用单独的线程更新UI
- 限制UI更新频率（每0.5秒更新一次）
- 只更新变化的部分，而不是整个界面

### 难点3：游戏状态管理

**问题**：游戏状态复杂，需要管理多个进度条、任务队列、角色数据等。

**解决方案**：
- 使用面向对象设计，将不同功能封装到不同类
- 实现清晰的 State 转换逻辑
- 添加详细的日志记录，便于调试
