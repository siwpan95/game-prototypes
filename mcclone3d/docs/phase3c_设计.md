# Phase 3-C 设计稿：顶点级 AO（平滑光照）

> 范围：**顶点级环境光遮蔽**（每个面四个角按邻格遮挡各自调暗）+ MC 的 **quad 翻转**。
> 纯观感特性：不改几何、不改面数、不改任何玩法判据（有单测钉着"只改颜色"）。
> 这一批的价值一半在特性本身，另一半在**代价的实测与优化**（§三：+24% → +17%）。

## 一、AO 是什么、为什么值得做

没有 AO 时，一个面四处**亮度相同**。后果是：两个面相交的**内角**（阶梯根部、墙角、
方块堆的缝）看起来是"平的"，整片建筑像纸糊的。

AO 按"这个角被别的方块夹得多紧"给每个角一个系数：

```
两条邻边都被挡        → 0 级（最暗）
否则                 → 3 − (邻边1 + 邻边2 + 对角)
```

`AO_FACTOR = (0.55, 0.72, 0.86, 1.0)`（手调表：关键是**单调**、且最暗不为 0 ——
归零会让角变成黑洞，反而丢掉体积感）。

**只看面外侧那一层**（法向再外一格的 3×3 环，去掉中心）：

* 中心那格不用查 —— **面剔除已经保证它是透明的**（否则这个面根本不会被画出来）；
* 因此每面只需 **8 次** `world.get`，不是"每角 3 次 × 4 角 = 12 次"
  （那 12 次里 4 次是重复的边邻居）。这个细节值 8% 的性能（见 §三）。

**遮挡 = 不透明**（`not is_transparent`，热路径用 `blocks.OPAQUE_IDS` 做集合成员测试）。
空气/玻璃/水都不算遮挡：水的口径在 MC 里一直有争议，这里一条说到底 ——
"不挡光就不挡 AO"，两个判据保持同一个来源。

## 二、quad 翻转（不做的话面内会出现一条斜向亮暗带）

一个四边形拆成两个三角形，**顶点色是沿共享对角线插值的**。若那条对角线两端
明暗差很大，三角形内部会出现一条可见的斜向渐变（原本应该只在角上暗）。

修法（MC 同款）：按 AO 选对角线 —— **让较暗的一对落在同一条对角线上**：

```python
if ao[0] + ao[2] > ao[1] + ao[3]:      # {0,2} 更亮 ⇒ {1,3} 更暗 ⇒ 用 1-3 连线
    索引 = (1,2,3), (1,3,0)
else:
    索引 = (0,1,2), (0,2,3)
```

只动**索引顺序**，不动顶点 ⇒ 面数/顶点数/位置/UV 全部不变（单测逐位比对）。

## 三、代价：先量，再优化（+24% → +17%）

**基线**（256³ 世界、47 万面、1024 区块）：全量建网格 **13.7s / 每区块 13.4ms**。

| 版本 | 每区块 | 相对基线 | 说明 |
| --- | --- | --- | --- |
| 无 AO | 13.62ms | — | 基线 |
| AO（初版） | 16.9ms | **+24%** | 每面现算偏移：`list(base)` + 按轴写下标 |
| AO（优化后） | 15.90ms | **+17%** | 预计算 3×3 环的坐标偏移 + 用集合判不透明 |

优化点两处，都是"少分配、少查找"：

1. **预计算 `_RING_OFF[face]`**：初版每个面都 `list(base)` 分配一次列表再按轴写下标，
   47 万面 = 380 万次分配。改成模块级预计算的 9 元组偏移（中心是 `None`）后不再分配。
2. **`blocks.OPAQUE_IDS`**：`is_transparent()` 要走"字典查 + 属性访问"两层，
   换成一次集合成员测试。这条路径一整世界跑几百万次。

⚠ 优化时踩了一个坑（**单测当场抓到**）：偏移里已经含了"法向走一格"，而 `face_ao`
里又给基准加了 `+out` ⇒ **法向被加两次**，采样到错误的层。
症状极具欺骗性：AO **恒为 1.0**（什么都没有被遮挡），
而"性能变好、面数不变、样本区块仍然有 65% 顶点被调暗"这些**旁观指标全都正常**
（因为错的是采样位置，不是"有没有调暗"）。只有"给定遮挡 ⇒ 该角变暗"这类**功能判据**
能抓住它。

**内核路径的代价更小**：`kernel.chunk_meshes` 里 AO 只占 +6.6%
（54.6 vs 51.3ms/区块）—— 因为那条路本来还要逐面查光照，AO 被摊薄了。

### 不做的事（评估过、没做）

* **每区块 18³ 透明位图**：理论上能把"剔除 6 次/方块 + AO 8 次/面"的查找全省掉，
  但纯 Python 填 5832 格本身就要几毫秒 ⇒ 实测不划算（没有明显收益就没上）。
* **按行滑动窗口共享环**：相邻方块的环有 6/9 重叠，但循环是 x→z→y 且带边界 break，
  滑动窗口会把热循环写复杂，收益又远小于上面两条。

## 四、怎么接进管线（默认关 vs 默认开）

* `mesh.build_chunk_mesh(..., smooth=False)` **默认关** ⇒ 与 Phase 3 的网格**逐字节相同**
  （老网格单测继续有效，也方便把"AO 是否生效"单独测）；
* 内核侧 `cfg['smooth']` **默认开**（纯观感，不影响任何玩法判据），
  demo / 截图脚本都走这个开关；
* 顶点色 = 面亮度 × 光照系数 × 红石信号系数 × **AO 系数**
  （四个乘子各管一件事，任何一个为"无"时都退化成 ×1.0）。

## 五、验收（全部实跑）

* 单测 **18 模块 285 项**（`test_mesh` 18 → **29 项**，`test_blocks` 7 → 8 项）：
  AO 表单调且最暗不为 0；无遮挡全亮；一条邻边 ⇒ 该侧两角变暗、另一侧不动；
  两条邻边 ⇒ 最暗（对角挡不挡都一样）；只挡对角 ⇒ 次亮；**同层邻块不影响该面**；
  玻璃/水不算遮挡；**六个面的外圈 8 格独立算**（不借实现的 `_RING_OFF`，
  避免"用实现测实现"）且**对面不受影响**；接进网格后**几何逐位不变、只改颜色**；
  **quad 翻转**（构造出该翻转的 AO 组合，断言走 1-3 对角线）；区块网格上面数/顶点数不变；
  `OPAQUE_IDS` 与 `is_transparent` **逐 id 一致**；
* headless **20 条**（新增 `ao`）：六条纯函数判据 + 几何不变 + "只变暗不变亮"
  （样本区块 41% 顶点被调暗）+ quad 翻转生效 + **代价 +17%（预算 <35%）**；
* **目视**：`shots/phase3c_ao_{off,on}.png`（同机位，装置是刻意搭的"内角大全"：
  三级阶梯 + L 形墙角 + 玻璃柱 + 下沉坑）；
* **差异图** `shots/phase3c_ao_diff.png`（逐像素差 ×4 放大）：亮带**精确落在每个内角**
  （阶梯根部/墙角/柱根 + 背景地形每一处台阶棱），**天空与开阔地面全黑**
  —— 一并证明两图取景一致（差异不是位移），AO 也没误伤平坦处。
  数值：26.9% 像素有差别、有差别处平均 38.5/765（约 5%）。

## 六、这一批不做（已知边界）

* **不做方块内的"阴影贴图"**（那是光照，本项目的天光/方块光是另一套，Phase 2-A）；
* 水不算遮挡（见 §一的口径说明）；
* AO 只有 4 级（MC 也是 4 级）；不做"每面独立的环境光颜色"（那要逐面光照探针）；
* 不与引擎的着色器联动（AO 烘在顶点色里，引擎侧一行没改）。
