## 二、本仓没有下界 —— 材料表是**重排**的（如实写明）

MC 的酿造建在"下界疣 + 烈焰粉 + 恶魂之泪"上，而本仓**没有下界维度**
（世界是一个有限箱体：地表 + 洞穴 + 村庄）。硬造"下界疣"只会让人觉得材料表是抄来的、
且无从获得。所以用本世界已有的资源重排一套，一一对应地保留 MC 的**直觉**：

| 药水 | 材料 | 为什么这么配 |
| --- | --- | --- |
| 治疗 | 金锭 | 贵重 = 治愈（MC 用闪烁的西瓜） |
| 迅捷 | 糖（麦子熬） | **与 MC 同款**：糖 = 迅捷 |
| 力量 | 煤炭 | 炽热 = 力量（对应 MC 的烈焰粉） |
| 抗性 | 铁锭 | 铁 = 护甲 |
| 剧毒 | 腐肉 | 腐败 = 毒 |

**不做"粗制药水"这一步**：MC 里它只是"必须先把水瓶变成基础药水"的前置点击，
本版没有下界疣，硬插一步只是多一次没有决策量的操作。

链条：`玻璃 3 → 玻璃瓶 3` →（对着水右键）`水瓶` →（酿造台 + 材料，8s）`药水` →（`Q`）`效果`。

## 三、效果一律写成"给定效果表算一个数"的纯函数

`speed_mult`（取最大）/ `damage_bonus`（取最大）/ `damage_scale`（取最小）/
`dot_rate`（相加）/ `instant_heal`。内核只负责在正确的时机取这些数：

| 接在哪 | 取哪个 | 判据（可精确断言） |
| --- | --- | --- |
| `step()` 的步行速度 | `speed_mult` | 同样 30 帧，迅捷走 **2.40 → 3.36 格**（= ×1.4） |
| `attack()` 的伤害 | `damage_bonus` | 僵尸掉血 4 → **6** |
| `hurt()` | `damage_scale` | 10 点伤害只掉 **6** |
| `_survival_step()` | `dot_rate` | 剧毒每秒 1 点、**停在 1 HP** |

三条**刻意的取舍**（都写进代码注释，不藏着）：

1. **迅捷只加步行、不加飞行**：飞是调试/建造手段（`F` 一按就有），让它也吃速度药水
   只会让"迅捷到底加了多少"说不清；MC 里迅捷也不影响创造飞行。
2. **抗性不减饥饿伤害**：`hurt()` 是所有伤害的唯一入口，受伤倍率如果无脑乘上去，
   饥饿就永远杀不死人 —— "饿不死"比"抗性太强"难查得多（玩家会停在 1 HP 像卡住了）。
3. **同类效果取较长者、不叠加时长**：叠加会让"喝两瓶 = 60 秒"变成刷时长的手段，
   而且 HUD 上没法表达。

## 四、剧毒为什么不另开一个受伤入口

剧毒要"按秒掉血"但**不能致死**（MC 同款；否则"喝毒药自杀"会变成玩家会用的技巧）。
最省事的写法是绕开 `hurt()` 自己减血 —— **不能这么写**：那"受伤"就有了第二个入口，
`stats['damage']`、死亡判定、抗性迟早会漏掉其中一条。

所以给 `hurt()` 加了 `floor` 参数（血量下限），剧毒走
`hurt(rate*dt, 'poison', floor=1.0)` —— 唯一入口这条性质保住了，
而"下限"是个纯粹的策略参数，放在签名里比藏在调用方清楚。

## 五、酿造台的"扣料"与"出货"必须分开

和熔炉同一条教训（Phase 1 踩过：借 `craft()` 当扣料工具 ⇒ 装炉那一刻产物就到手，
烧完再给一次、一炉发货两次）。`brew_load()` 只扣料并记住 `output`，
`brew_step()` 到点才 `give`。

另外两条：
* **一炉没完不许再装**（否则第二次装料会把第一次的料白白吃掉）；
* 拒绝时**一点料都不动**（判据里直接比对整个背包字典）。

## 六、★ 本批最大的发现：整个世界的贴图大了 8 倍（从 Phase 0 起）

### 症状

酿造台的贴图"看不清"：2 格外就是一团平滑的灰。用棋盘格对照否掉了"贴图太细"，
再用"给每张贴图一个独一无二的颜色"追下去，发现**铺 3 格的同一种方块里只有 1 格
出现纹理特征** —— 这不像采样问题，像**密度**问题。

### 取证

一格 16×16 的石头贴图，映射到屏幕上只占 **2×2 个色块**。算一遍就明白了：

```
uv_projection_for:  scale = 1/(cols × tile_size) = 1/8      # 跨 1 格世界距离，u 走 1/8
_atlas_uv（旧）:     fu = frac(u); 再线性映射进该贴图的矩形
                    ⇒ 面内只走完 1/8 ⇒ 只显示这张贴图的 1/8
```

而 `atlas_rect()` 给的矩形是**整张贴图**的形状 ⇒ 两者对不上：
面内 UV 只覆盖矩形的 **12.5%**，于是整张贴图被放大 8 倍铺在 1 格上。

**自洽的旁证**：相邻方块显示的是相邻的 1/8 切片 ⇒ **花纹跨格连续**，
远看"像那么回事"（这正是当年没被发现的原因），而近看就是一团团糊斑。
CLI 的 `mesh` 条当时**是绿的** —— 它只断言"面内 UV 跨度 = 1/图集列数"（图集空间，
1/cols 是对的）与"跨格连续"（也对），**没有任何一条断言"面内要铺满那张贴图"**。

### 修法与防回归

新增 `_atlas_uv_quad(uvs, tile)`：**按整面**把图集空间的 u/v 换算成贴图内坐标
（`u × cols − 该面起点所在的格号`），四角于是落在 `[0,1]` 上。

⚠ 一个必须避开的边界：**不能在每个角上各自 `frac`** —— 面正好跨满一格时末角落在整数
边界，`frac(1.0) = 0.0` 会把它折回起点 ⇒ **整面插值成同一个纹素**（贴图变成一块纯色）。
所以是"整面减一次格号 + 夹到 [0,1]"，而不是逐角取小数。
（比一格宽的面只有生物盒模型的部件，被夹住 = "一张贴图铺满整个部件"；
生物用的是无花纹的羊毛贴图，视觉一样 —— 明写的取舍。）

**防回归**：CLI 的 `mesh` 条加了第 ⑤ 组判据 —— **面内 UV 跨度 ÷ 贴图矩形宽度必须 = 1.0**。
这条判据以前**不存在**，所以这个错误才能活到 Phase 3-F；现在它红一次就说明密度又错了。

### 与 Phase 3-E 那条"mag_filter 是普通属性"的关系

两条都是真的，而且症状一模一样（"近看毛玻璃"）：

* **第一因是密度**（本批修的）：贴图被放大 8 倍铺在一格上；
* 第二因是过滤（3-E 修的）：`GL_LINEAR` 把已经放大的贴图再抹平一次。

只修过滤 → 从"糊"变成"大而软"；只修密度 → 从"糊"变成"小而糊"。
**两条都修完**，近景才是真正的 16×16 像素材质（截图见 `shots/phase3f_*`）。
教训：**同一个症状可以有两个独立的原因**，"找到一条能解释现象的原因"不等于"找全了"。

## 八、这一批不做（已知边界）

* **不做酿造界面**：右键酿造台 = "把水瓶 + 背包里第一种可用材料放进去"。
  自动挑的规则照 `BREWS` 的顺序（确定、可在日志里核对），不是"随便挑一个"。
* **不做"延长版 / 增强版"药水**（MC 的红石延长、荧石增强）。
* **不做喷溅药水 / 药水箭**：本版没有投掷物。
* **药水不可堆叠**（`stack=1`）：16 瓶一组的写法会让"喝一瓶少一瓶"的记账与 hotbar
  那一格的表现不一致（`selected_item()` 只看 id、不看数量），一叠瓶子喝到最后会
  变成"明明还有却显示空了"。`test_items` 的堆叠断言已相应放宽并写明理由。
