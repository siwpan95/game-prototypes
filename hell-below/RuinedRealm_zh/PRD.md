# Ruined Realm — 产品需求文档 (PRD)

## 1. 项目信息

| 字段 | 值 |
|---|---|
| 项目名称 | `ruined_realm` |
| 项目类型 | 类杀戮尖塔的纯文字解密冒险游戏 |
| 技术栈 | Python + Tkinter（MVC 架构） |
| 界面语言 | 纯英文 |
| 输出路径 | `C:\Users\13122\Desktop\stay\hell below\en\Ruined Realm\` |
| 架构参考 | text_decrypt_game MVC 架构 |

### 原始需求复述

基于网络小说《综网：地狱之下-第十一卷 墟境》的世界观，制作一款类杀戮尖塔（Slay the Spire）的纯文字解密冒险游戏。玩家扮演维修工普雷尔·查内姆，坠入由"被删除的东西"构成的数字冥界"墟境"，通过探索、解密、资源管理来生存并揭开遗忘的家族悲剧。采用 Tkinter 制作简单图形界面，支持鼠标交互，纯英文版，多结局分支。

---

## 2. 产品目标

| # | 目标 | 衡量标准 |
|---|---|---|
| G1 | **沉浸式叙事体验**——让玩家在文字交互中感受墟境的诡异与孤独氛围 | 单次游戏时长 ≥ 40 分钟；玩家可理解核心剧情并完成至少一条主线 |
| G2 | **策略性决策与资源管理**——每次选择都有代价，化身完整性驱动玩家思考 | 玩家每局需做出 ≥ 15 次有意义的分支选择；无"无脑最优路径" |
| G3 | **可重玩性**——多结局+随机地图+碎片收集驱动多次游玩 | 至少 3 个不同结局；不同路线可解锁不同记忆碎片 |

---

## 3. 用户故事

1. **US1** — As a *narrative adventure fan*, I want to *explore a node-based map of Ruined Realm* so that *I can choose my own path through the story and feel the tension of each decision*.

2. **US2** — As a *puzzle solver*, I want to *collect memory shards and use my eye scanner to uncover hidden signals* so that *I can piece together the tragedy behind the Ruined Realm and unlock new story branches*.

3. **US3** — As a *survival strategist*, I want to *manage my avatar integrity carefully* so that *I don't lose body parts and can survive long enough to reach the end*.

4. **US4** — As a *completionist player*, I want to *discover multiple endings through different choices and shard combinations* so that *I can experience the full depth of the story*.

5. **US5** — As a *casual player*, I want to *save and load my progress at bulb checkpoints* so that *I don't have to restart from the beginning every time*.

## 4. 需求池

### P0 — 必须完成（MVP）

| ID | 需求 | 描述 |
|---|---|---|
| P0-01 | 节点式地图系统 | 类杀戮尖塔的分支地图，玩家点击节点选择路线；每个节点类型：事件、战斗（信号冲突）、休息（灯泡）、商人（幽灵协议用户）、谜题、Boss |
| P0-02 | 事件/对话引擎 | 每个节点展示文字叙事+2~4个选项；选项可触发状态变化、获得物品、解锁碎片、改变后续路线 |
| P0-03 | 化身完整性系统 | 核心资源，初始值100%；快速移动（选择"跑"选项）、受伤、缓存合并均会降低；降至0%则游戏结束；可用电缆（道具）修复 |
| P0-04 | 义眼扫描 | 主动技能，可检测当前节点的隐藏信号/物品/危险；有冷却（如每3个节点可用1次）；揭示隐藏选项 |
| P0-05 | 记忆碎片收集 | 不同颜色碎片（金色=辛迪嘉、红色=康采恩、蓝色=幽灵协议）；收集后可查看碎片内容；特定碎片组合解锁隐藏结局 |
| P0-06 | 墟境生存法则 | 移动选项有"慢走"（安全）和"快跑"（风险+节省时间）；靠近NPC超过一定交互次数触发缓存合并（损失完整性）；按住喉结（按键/选项）可压制信号 |
| P0-07 | 多结局系统 | 至少3个结局：逃离墟境、与辛迪嘉团聚、被鬼差回收；结局由碎片收集度+关键选择决定 |
| P0-08 | 存档系统 | 在灯泡（安全节点）可存档；支持多存档位 |
| P0-09 | Tkinter 主界面 | 文字显示区（主叙事）+ 选项按钮区 + 状态栏（完整性、碎片数、当前位置）+ 小地图面板 |
| P0-10 | MVC 架构落地 | 严格遵循 text_decrypt_game 架构目录结构和模块划分 |

### P1 — 应该完成

| ID | 需求 | 描述 |
|---|---|---|
| P1-01 | 信号冲突（战斗系统） | 文字描述+选项驱动的"战斗"：面对鬼差或异常信号，选择压制/对抗/逃跑，每回合消耗完整性或道具 |
| P1-02 | 背包系统 | 管理已获得的物品：电缆（修复完整性）、灯泡碎片（临时安全点）、数据包（信息道具） |
| P1-03 | NPC 交互 | 老鬼（教学+交易）、辛迪嘉（关键剧情）、鬼差·辛（威胁+特殊交互） |
| P1-04 | 小地图可视化 | 在侧边栏展示已探索的节点地图，当前位置高亮，未探索节点灰显 |
| P1-05 | 游戏内时间/回合 | 每次移动推进1回合，某些事件有回合限制（如"鬼差巡逻3回合后到达"） |
| P1-06 | 音效与简单动画 | 文字逐字显示（打字机效果）、关键事件音效（可选） |
| P1-07 | 新手引导 | 开场通过老鬼NPC教学生存法则，引导玩家理解核心机制 |

### P2 — 锦上添花

| ID | 需求 | 描述 |
|---|---|---|
| P2-01 | 难度选择 | 简单/普通/困难，影响完整性消耗速率和鬼差巡逻频率 |
| P2-02 | 成就系统 | 收集全部碎片、零死亡通关、10回合内通关等 |
| P2-03 | 终极作弊码 | "10-10-10"——对应原著彩蛋，输入后触发特殊内容 |
| P2-04 | 自定义主题 | 暗色/亮色主题切换 |
| P2-05 | 额外结局 | 基于碎片组合解锁隐藏结局（4th+结局） |

### 5.2 关键交互设计

| 界面区域 | 交互方式 | 说明 |
|---|---|---|
| 主叙事区 | 只读显示，自动滚动 | 打字机效果逐字显示文字；新内容追加，旧内容可回滚查看 |
| 选项按钮区 | 鼠标点击 | 2~4个选项按钮，点击即选择；灰色=不可用（需义眼扫描解锁） |
| 小地图面板 | 鼠标悬停/点击 | 悬停显示节点简要信息；点击未探索相邻节点=移动到该节点 |
| 状态栏 | 实时更新 | 完整性条（颜色渐变：绿→黄→红）、碎片计数器、回合数 |
| 底部功能栏 | 鼠标点击 | 打开背包面板、碎片查看面板、存档/读档、设置 |

### 5.3 特殊界面

- **背包面板**：弹窗/侧边抽屉，显示已获得物品列表，点击物品查看描述
- **碎片查看面板**：弹窗，按颜色分类显示已收集碎片，未收集的显示为"???"
- **存档面板**：3个存档位 + 1个自动存档位，显示存档时间和当前进度
- **对话窗口**：NPC对话时，主叙事区显示对话内容，选项区显示对话选项

### 5.4 视觉风格

- 暗色主题为主（深灰/深蓝底色），契合墟境氛围
- 完整性条用渐变色（绿→黄→红）
- 碎片图标按颜色区分（金色/红色/蓝色）
- 文字字体：等宽字体（如 Consolas），营造终端/数字感
