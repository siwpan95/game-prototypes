## 这个目录是干什么的

本仓的架构判断、实测证据和长期约定都放在这里，而不是散落在 README 与提交信息里。
判据很简单：**别人以后要照着做的东西放 `spec/`，只发生过一次的事放 `records/`。**

## 怎么加一份文档

1. 想清楚它属于哪一类（上面那张表的判据）。
2. 放对目录：规范不带日期（效力日期写在头部），记录**必须**带日期或月份卷。
3. 登记进 [`INDEX.md`](INDEX.md)——**没登记等于不存在**，这是本枢纽唯一的硬要求。
4. 规范要带效力声明头（编号 / 效力 / 状态 / 生效 / 最后修订 / 适用面 / 承载体 / 引用格式）。
5. 引用规范时写 `SPEC-101 §阶段 M2` 这种形式，**编号只追加不重编**。

## 与治理门禁的关系

本仓没有 Node 治理运行时，因此 `pnpm run check:governance` 在这里**不适用**，
也不会假装跑过。规则按条目人工机械核对（路径不写死盘符、Python 文本读写显式 `encoding=`、
产物与字节码不入库、编号只追加不重编、自称事实源必须带时点）。
判据来源：分发版治理落地 `governance/docs/`（在 DSH 检出内）。
