阻塞性问题（必须修复）

P0

1. 章节解锁机制在主题模式下完全失效

ThemedGameEngine._trigger_plot_event() 覆盖了父类 GameEngine 的新版章节解锁逻辑。父类基于"完成任务数"逐步解锁章节，但子类用的是旧的 plot_bar.increment(20) 随机事件逻辑，从不更新 plot_chapters 的 unlocked/completed 状态。导致主题模式下章节永远不解锁、剧情条永远 0%。

修复方案：删除 themed_engine.py 中的 _trigger_plot_event 方法，直接继承父类逻辑。或在子类中调用 super()._trigger_plot_event()。
P0

2. save_game() / load_game() 方法不存在

tkinter_ui_themed.py 第 568/573/581 行调用 self.engine.save_game() 和 self.engine.load_game()，但引擎只定义了 save(filepath) 和 load(filepath)。点击保存/加载按钮必定崩溃。

修复方案：在 ThemedGameEngine 中添加 save_game()/load_game() 便捷方法，内部调用 save()/load() 并使用固定存档路径。
P0

3. 保存/加载不完整 — 章节和任务状态丢失

save() 方法没有保存 plot_chapters、active_tasks、_quests_completed_total、current_monster 等关键状态。加载后章节进度归零、活跃任务清空。

修复方案：扩展 save() 序列化全部游戏状态，load() 对应反序列化。

架构问题

P1

4. 骨架/血肉分离不彻底

用户明确要求"游戏本体仅负责运行逻辑，主题对应文案"。但以下两处仍使用硬编码数据：

• Character._learn_spell() — 法术名硬编码为"火焰之箭/冰霜之触"等，不同主题学到的是同一套法术
• _populate_active_tasks() — 活跃任务目标硬编码为"一些巨眼怪/一些洞穴人"等，与主题无关

修复方案：在 GameTheme 基类中增加 spell_pool 和 task_targets 字段，由各主题填充。引擎通过 self.theme 获取。
P1

5. ThemedGameEngine._buy_equipment 只支持 4 种装备槽

子类重写的 _buy_equipment() 只处理 weapon/armor/helmet/boots 四种，而引擎定义了 11 个装备槽（shoulder/chest/arms/gloves/underarmor/pants/legs/shins）。大量装备槽永远不会被商店装备填充。

修复方案：统一使用父类的 slot_map 逻辑，或扩展主题数据中的 item_type 以覆盖全部槽位。
P1

6. _init_game_data 初始化的默认数据在主题模式下完全冗余

GameEngine._init_game_data() 初始化了 4 个默认怪物和 4 个商店物品，但 ThemedGameEngine 重写了 _start_new_monster()、_start_new_quest()、_buy_equipment()，使用主题数据。这些默认数据从不被使用，浪费内存且造成混淆。

修复方案：将 _init_game_data() 改为空方法或仅保留空列表，由子类按需覆盖。

机制偏差

P1

7. 经验获取方式不符原版 PQ

原版 PQ 经验是随时间自动获得（每 tick 获得 MaxProgress/1000 点），不是击杀怪物获得。当前实现在 _kill_monster() 中一次性给予 exp_reward。这与之前从 C++ 源码确认的机制矛盾。

修复方案：在 _game_tick() 中每 tick 增加 exp_bar.max_value / 1000 经验，击杀怪物不再直接给经验（或仅给少量奖励经验）。
P2

8. 战斗 HP 显示 bug

_kill_monster() 第 584 行：HP: {self.current_monster.hp}/{self.current_monster.hp + damage}。分母用的是"当前HP+本次伤害"，不是怪物的最大HP，显示的进度条比例不正确。

P2

9. Spell.__str__ 存在死代码

Spell.__str__() 计算了 lvl（罗马数字）但没有使用，直接返回 f"{self.name}"。
