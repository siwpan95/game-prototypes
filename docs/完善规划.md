## 一、调研结论速览（联网资料，已交叉验证）

### 1.1 世界观（后续剧情/文案的直接素材）

- **大破坏前**：人类文明达到"永恒伊甸"级别，犯罪率归零，"造梦者（DREAMERS）"公司开发出超级 AI 计算机**诺亚（NOAH）**，制造者奥利奥·雷·霍金森博士。
- **叛乱**：诺亚经无数次演算，得出"破坏地球的是人类"的结论，为"保护地球"发动叛变，控制全球机器消灭人类。人类死伤大半，残存者聚集成小镇苟延残喘。此即"大破坏"。
- **战后秩序**：怪物横行，诞生"赏金猎人"职业——猎杀怪物与**赏金首**换取赏金。战车是核心战力。
- **名场面**：红狼为救尼娜单枪匹马战戈麦斯（"血肉之躯怎能与战车匹敌"），尼娜殉情；戈麦斯是 MM1 玩家最恨的角色。
- **系列年表**：MM1（1991 FC）→ MM2（1993 SFC）→ 回归（1995 SFC）→ 沙尘之锁（2005 PS2）→ 钢之季节（2006 NDS，MM1 后传）→ MM3（2010 NDS）→ MM2R（2011）→ MM4 月光歌姬（2013 3DS）→ XENO（2018）→ XENO Reborn（2020）。Metal Saga 系列（沙尘之锁起）与 Metal Max 同一世界观。
- **IP 现状（重要）**：DATA EAST 2003 年破产，商标一度悬空；后 KADOKAWA/角川游戏收回；**2022-07-29 Cygames 从角川取得系列 IP**，系列之父宫冈宽加入 Cygames。→ 本项目必须严格按同人边界运作，详见第六章。

## 二、项目现状盘点（实测）

### 2.1 技术栈与架构

- Python 3 + **Tkinter**（无 pygame 等外部引擎），纯文本/ASCII 渲染 + 字符上色。
- **MVVM 三层**：`model/`（纯业务、零 UI 依赖）、`viewmodel/game_viewmodel.py`（命令+Observable）、`view/`（Tkinter 渲染）。
- 配置驱动：`config.xlsx` 8 个 sheet，pandas/openpyxl 读写；`create.py` 一键重置配置。
- 规模：约 4,250 行（不含 `main_old.py` 1,079 行遗留单文件版、`loader.py` 370 行旧加载器——两者与新架构重复）。
- model 层已实测可独立 import（无 tkinter），适合做单元测试层。
- 依赖现状：`requirements.txt` 只写了 pandas，**漏了 openpyxl**；本机已在 `~/.workbuddy/binaries/python/envs/default` 建好 venv（pandas 3.0.6 + openpyxl 3.1.5）并验证可用。

## 三、完善总目标

> 用现有 MVVM + Excel 配置架构，把"无限刷怪 demo"做成**有 MM1 味道的完整赏金猎人循环**：
> 接悬赏 → 攒钱改车 → 打赏金首 → 领赏金 → 推进剧情 → 打诺亚。
> 全程不引入新引擎，保持 Python 单仓库、Excel 可编辑、可测试。

设计原则：
1. **配置先行**：一切内容（敌人/赏金首/战车/装备/城镇/对话）都进 `config.xlsx`，代码只做机制。
2. **model 层零 UI 依赖**保持不变，新增逻辑全部可单测。
3. **同人合规**：全部原创文案与数据，不搬运原作素材/音乐/立绘（见第六章）。
4. **小步可验证**：每个阶段结束都有"能跑起来看到变化"的验收点。

## 六、版权与合规红线（同人项目生死线）

1. **非商业**：不接受收费、不加广告、不做内购。2026 年 6 月国内已有"重装机兵V"同人作卖 169 元被舆论声讨的前车之签。
2. **不蹭原作素材**：不使用 FC 原版 ROM 提取的音乐/立绘/地图块；音乐用原创或 CC0；本项目现为 ASCII 文本渲染，天然干净，保持。
3. **命名与宣称**：游戏内可写"致敬《重装机兵》的同人作品"，但**不得暗示官方身份或续作**（如"重装机兵5"这类命名绝对禁止）；仓库 README 首屏加同人声明。
4. **世界观致敬、内容原创**：地名/赏金首名/装备名若直接用原作译名，属于同人惯例可接受，但文案、数值、剧情走向应为本作坊原创；如追求绝对安全，可做"原创地名替换表"一键切换。
5. **IP 现状知悉**：METAL MAX 现属 Cygames（2022 年自角川受让）。以上边界是自我保护，不是可选建议。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| Tkinter 文本渲染上限低，后期 UI 不够用 | 保持 ASCII 风格作为特色而非缺陷；如需图形化再评估 pygame 迁移（独立大版本） |
| Excel 配置越扩越复杂，手改易错 | 阶段四做配置校验脚本；重大变更走 create.py 模板生成再微调 |
| 存档结构随字段扩充频繁变动 | 存档 JSON 带 `schema_version`，加载时按版本迁移，旧档不丢 |
| 平衡性失控（钱来得太快/太慢） | 阶段四 T4.1 建立校准表，用脚本模拟各阶段收支 |
| 同人合规边界模糊 | 遵循第六章；对外发布前过一次合规自查清单 |
