## 一、现状（实测 2026-10-16）

| 事实 | 证据 |
| --- | --- |
| 14 种谜题种类，逻辑与 pygame 界面原先耦合在 1584 行 `ui.py` 里：事件与绘制两条硬编码 14 路 `isinstance` 链，注册表两份 | `goto` 之前的代码；现由 `puzzle_service/registry.py` 取代 |
| 两个版本各自导出同名顶层模块（`engine`/`gameplay_pool`/...），同进程只能加载一个 | `shared/paths.py` 的注释与 `bootstrap_import_path(build)` 的单版本约束 |
| 6 种谜题的 `check_answer` 忽略入参、只读自身状态 | `puzzle_service/registry.py` 的 `answered_by="action"` 与 `tests/test_service.py` 的断言 |
| 4 种谜题对类型不对的入参抛 `ValueError`/`TypeError` | `docs/records/text-adventure-boot-crash-fix_2026-10-16.md` 的输入健壮性表 |
| 谜底不会进入视图模型 | `tests/test_views.py::test_views_never_contain_the_solution` |

## 二、目标架构（已落地部分）

```
浏览器 (public/)                     渲染层：把视图模型映射到语义 HTML，一个客户端渲染全部 14 种
   │  POST 动作 + SSE 快照
Node Cordis 宿主 (src/)              编排层：插件装载、生命周期、HTTP/SSE；不含谜题逻辑
   │  JSON-RPC 2.0 over stdio (src/core/bridge.mjs ↔ python/rpc_server.py)
Python 谜题进程 (puzzle_service/)    领域层：状态、规则、计分、视图模型——唯一真相源
   └─ pygame 客户端 (text_adventure*_zh/ui.py)  共存的旧渲染层，未删除
```

三层职责的判据来自调研结论：**被多个消费者共享且必须一致的东西才进内核**，
其余一律做成插件或数据（见 `records/platform-research-2026-10/02-platform-architecture.md`）。

## 三、分阶段路线

### 阶段 M0 · 可玩性修复（已完成 2026-10-16）
修掉两个版本都启动失败的问题，补上共享层、无头冒烟测试、可复现的环境重建脚本。

### 阶段 M1 · 浏览器可玩（已完成 2026-10-16）
- 视图模型 + 原语白名单（10 个原语：`text/field/options/list/clues/grid/sequence/keyboard/colors/board`），
  未知原语**响亮失败**而不是渲染空白页（实测：`npm run smoke` 的「unknown primitive」一项）。
- 传输选 **POST 动作 + SSE 快照**：回合制不需要长连接；SSE 自带断线重连与 `Last-Event-ID`，
  而 WebSocket 协议层不含恢复，Node 内置 WebSocket 只有客户端、没有服务端。
  来源：[Node.js WebSocket 现状](https://nodejs.org/learn/getting-started/websocket)（检索 2026-10-16）。
- 可访问性：纯颜色玩法同时给符号与文字（WCAG 2.2 **SC 1.4.1** 要求不能只靠颜色传达信息），
  每个鼠标操作都有键盘通路。来源：[What's New in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)（检索 2026-10-16）。
  注：二手博客常把 2.4.13 Focus Appearance 误标为 AA，实为 AAA ——按 W3C 原文核对。
- **未验证项（已消除，2026-10-16）**：浏览器端曾只做到 HTTP/SSE/客户端语法与 DOM 绑定层面的
  自动检查。现由 `src/browser_e2e.mjs` 用真浏览器（Playwright，`npm run e2e:browser`，
  已进 `npm test`）跑 16 项检查覆盖：加载与控制台零错误、SSE、14 种可选、开局渲染、
  错答反馈、提示、点击格子、键盘 `f` 插旗、右键插旗、方向键操作 2048、
  颜色不单独承载信息、答题结果、每日一题、分享卡片、进度显示。
  它当场抓到 favicon 404 与两处**测试断言写错**（产品行为本身正确）。
- 第三个客户端（命令行）在同一份视图模型上落地，未改动服务端任何代码——
  这是「渲染层可替换」这一主张目前唯一的实证。
- **label 契约**：视图模型发 label **键**（`label_key`）加一份英文默认文本，
  文案由各客户端决定（只有客户端知道用户读什么语言）。键的全集在
  `puzzle_service/views.py` 的 `LABEL_KEYS`，测试要求每个 field 节点都带已声明的键。

### 阶段 M2 · 内容包（进行中：加载与首个数据包已完成 2026-10-16）
把谜题内容从代码里抽出来，才能谈「内容供给」和「难度标定」。
- 数据格式：`manifest.json` 带**双版本字段**（`format_version` + `min_engine_version`），
  先例是 Minecraft 的 `pack.mcmeta`；正文用 JSON Schema（2020-12）校验，迁移用幂等注册表。
- 内容包**不得包含可执行代码**（不引入 Python 表达式、不引入 `eval`），这与「进程边界才是唯一真边界」的
  调研结论一致：`node:vm` 官方明确不是安全机制，
  来源：[Node.js VM](https://nodejs.org/api/vm.html)、[Node.js Permissions](https://nodejs.org/api/permissions.html)（检索 2026-10-16）。
- 首发范围：把 5 种**内容型**谜题（谜语、猜单词、单词接龙、字母重排、填字）从模块内置题库
  迁移到 `content/packs/core-zh/`（154 条），由 `scripts/build_content_pack.py` 从模块派生，
  `--check` 用于 CI 防漂移。
- **不做**什么：`pattern`（数列规律）是**生成型**而非内容型（`puzzle_type = "generated"`），
  它的"题目"由算式生成，不存在题库可迁移——需要的是难度参数化，不是内容包。
  判断依据是各谜题类自己的 `puzzle_type` 与 `content_kind`，不是"看起来像有内容"。
- 校验器按种类写规则（选项下标越界、重复条目、单词长度、填字格覆盖与坐标越界、
  梯子池词长一致、**谜底字段不得出现代码**），并且**加载即校验**：坏包响亮报错并退回家底题库，
  同时把原因写到 stderr——不许静默降级。
- 待办（本轮实测暴露）：视图模型里的 `field.label` 目前是服务端写死的英文字面量，
  而服务端并不知道哪个客户端在渲染。干净的做法是服务端发 **label 键**（如 `answer`、`next_word`），
  由客户端出文案；目前终端客户端只能做展示层翻译，属于临时处置。

### 阶段 M3 · 网页编辑器
编辑态用**只读开关**而不是第二套编辑器（可核查先例：Excalidraw 的 `viewModeEnabled`、
JSON Forms 的 `readonly`）；撤销重做用快照栈即可，协同编辑（Yjs/CRDT）在这一阶段是过度设计。
调研结论标注：**未找到**文字解谜类开源关卡编辑器可作直接参照。

### 阶段 M4 · 每日节奏与分享（进行中：每日一题已完成 2026-10-16）
竞品扫描的结论是平台卖的是「每日节奏 + streak + 无剧透分享 + 档案」，不是谜题种类数量。
- 每日一题**不需要后端**：按本地日期从预打乱列表取题（可核查先例：Wordle 的做法，
  来源：[Hacker News 讨论](https://news.ycombinator.com/item?id=30435522)，检索 2026-10-16）。
- 本仓实现：日期经 SHA-256 变成种子（**不用 `hash()`**：它按进程加盐，会导致每次重启换题），
  种子同时驱动「选哪种」与「出哪道」；14 种**逐一验证**同种子可复现（`tests/test_daily.py`）。
  种子走谜题自身的生成器（`self._rng()`），**不重播全局 `random`**——否则会污染同进程里的其它会话。
- 分享卡片只输出**结构信息**（猜测图样，不含答案），剪贴板即可，无需账号。
  已实现：`profile.share` / `GET /api/share` / CLI `share` / 网页「分享卡片」按钮，
  并且卡片自带「不含谜底，可安全分享」的说明。
- 变现排在留存验证之后；调研**未找到**可核查的 ARPDAU/eCPM 数据，不要据此编数字。
- 已实现：连续天数（**从记录推导**，不存计数器：跨缺口自动归零；今天未玩时昨天结束的连续仍有效）、
  每日记录（日期/种类/完成/得分/尝试/用时，**不含谜底与题目内容**）、
  原子写入存档（临时文件 + `os.replace`）、坏档案响亮报错并按空档案继续。
  入口：`profile.info` / `GET /api/profile` / CLI `profile`；网页进度行。
- 已实现：**历史回看**（`profile.history` / `GET /api/history` / CLI `history`；新在前，
  且不显示锚点日之后的记录——回看旧日子不该剧透后面几天）；
  **图形化分享卡片**（`share_card_svg`，独立 SVG，文字仍是 `<text>` 所以屏幕阅读器读得到、
  测试断言得了；`profile.share.svg` / `GET /api/share.svg` / CLI `card` / 网页「卡片图」）；
  **可访问性自动审计**（axe-core 注入真页面，只把 serious/critical 当失败，
  覆盖菜单/网格/颜色/输入四个画面，当前 0 violations）。
- 已实现：**历史按题号回看**（见上）；分享卡片的图形化版本（见上）。
- 未做：英文卡片文案（与服务端目前只有 zh 内容包一致，与 label 键是同一类问题，见 §阶段 M5）；
  平台分享集成（调研结论：文本/图片 + 剪贴板已覆盖绝大多数场景，平台集成会把外部 API 的易变性引进来）。

### 阶段 M5 · 双实现收敛（已完成 2026-10-16，谜题池部分）
`text_adventure/` 与 `text_adventure_zh/` 曾是两份并行实现。**先量后动**的结果是：
17 对文件、约 1580 行/份，差异约 200 行且**几乎全是文案**——逻辑本来就只有一份，
所以合并 = 把文案抽出来（`gameplay_pool/messages.py`），而不是重写逻辑。

- 语言成为构造参数：`MathPuzzle(difficulty="easy", lang="zh"|"en")`；
  `puzzle_name` 保留类属性（默认语言）+ 实例属性按语言覆盖，**客户端代码一行未改**。
- 注册表改按 **(语言, 种类)** 建键：原按种类名建键，进程里先注册的语言会赢下之后所有请求
  （合并当天由比对抓到的真缺陷）；未注册的语言**报错**而不是回退到另一种语言。
- 内容按语言分包：`content/packs/core-zh` 与 `core-en`（各 154 条，均由旧模块派生）。
- 两处中英**本来就不同**的行为保留为按语言分支，而不统一：填字提示策略、颜色显示用词。
  统一它们等于悄悄改掉一版行为。
- 删除了两份重复的 `gameplay_pool`（git 记为 rename）：同名包两份共存时，
  导入哪一份取决于 `sys.path` 顺序——这正是要消除的东西。
- 等价性证据：`scripts/_audit_parity.py` 在同一随机种子下逐项比对统一实现与两版旧实现，
  两版各 **0 problem**；只允许两类已登记差异（填字提示策略、谜语提示 answer→option）。
- **未做**：两个 pygame 客户端（`engine`/`ui`/`events`/`domain`，各约 1600 行）仍是两套。
  这条渲染路径已被 Web 与终端客户端取代，合并收益低于风险，留作独立任务。
- **未做**：第三种语言。机制已就位（`messages.py` 加一列 + 一个内容包），无真实需求时不造数据。

## 四、红线

1. **不可信插件绝不同进程**：进程边界是唯一可信边界。
2. **内容包不含可执行代码**；归档条目名不可信（防 Zip Slip），解压前校验路径。
3. **跨进程调用必须带超时与字节上限**（桥已实现：每请求超时、请求体上限 1 MB）。
4. **谜底不进视图模型**（已有测试守着）。
5. **谜题 id 唯一**；同名不同类必须拒绝注册（已有测试守着）。
6. **不假绿**：视图原语未登记、插件未装载、服务未 ready，都必须看得见地失败。
