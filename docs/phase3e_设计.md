# Phase 3-E 设计稿：附魔（经验 / 附魔台 / 五条附魔）

> 范围：**经验（XP）→ 附魔台 → 五条附魔 → 真的改玩法**，最后落在存档 v4 上。
> 「酿造」是同一件路线图条目（附魔与酿造）的另一半，单独一批做。
>
> 本批最贵的一条不在附魔里：**顺手抓到一个从 Phase 0 就存在的渲染静默失效** ——
> `pyglet 2.1` 的 `Texture.min_filter/mag_filter` 是**普通属性**，事后赋值不碰 GL，
> 于是"必须 NEAREST"这句注释写了几周、实际一直在用 `GL_LINEAR`（§六）。
> 它把本批的目视验收直接卡住了，也解释了为什么所有近景截图都像毛玻璃。

## 二、经验：**只存点数，等级是派生的**

```
升到第 L 级需要的累计点数：xp_total(L) = L² + 6L        （本级长度 2L + 7）
整数反函数：              level_for(xp) = (isqrt(4x + 36) − 6) / 2
```

选这个闭式而不是查表，是为了让"点数 ↔ 等级"是**精确互逆**的（单测穷举 0..200），
不会出现"表与公式对不上"这种只能在玩家身上才发现的问题。存档里**只写 `xp`**：
等级存进去就等于承认"档里的等级可能和点数不一致"，那是不可自愈的脏数据
（与"光照/红石信号不进档"同一条口径）。

**花等级 = 扣点数**，而且必须保证"等级恰好降 n 级"。这里有个容易写错的地方：

> 直接减"本级长度"会**越界** —— 例如 5 级、本级已得 16 点（5 级长 17），
> 减一级后是 `40 + 16 = 56`，而 5 级的起点是 55 ⇒ **仍然是 5 级**，白花。

所以 `spend_xp()` 走"**按比例保留本级进度**"：`xp' = xp_total(L−n) + keep × span(L−n) / span(L)`。
单测穷举 `xp ∈ 0..400 × n ∈ {1,2,3,4,9}` 钉死两条不变量：等级恰好降 n、且 `xp' ≤ xp`。

**经验来源**（都走 `add_xp`，单次封顶 50 点防"一笔巨款跳几十级"）：
矿石（煤 1 / 铁 2 / 金 3 / 钻 5）、烧成一炉 +2、击杀（羊猪 2 / 僵尸 5 / 村民 0）。
挖土**不给**经验 —— 给的话"经验"就变成"挖土刷级"。

> ⚠ **创造模式也给经验**（与 MC 不同，是有意的）：demo 默认就是创造模式，
> 若创造模式不给，附魔这条链路在默认玩法下**完全看不见** —— 没法试、没法截图、
> 没法目视验收。本版没有等级排行榜之类的东西，代价可接受。这条如实写在
> `kernel.add_xp` 的 docstring 里，不假装与 MC 一致。

## 三、五条附魔：每一条都必须**能被观测到**

| 附魔 | 上限 | 作用 | 判据（可精确断言） |
| --- | --- | --- | --- |
| 效率 | V | 挖掘速度 ×(1 + 0.30·等级) | `dig_time` 与公式对拍（分母里多一个倍率） |
| 耐久 | III | 每 (1+等级) 次使用才磨损 1 点 | 10 点耐久的镐 **恰好** 40 次才断 |
| 时运 | III | `floor(roll × (等级+1))` 个额外掉落 | 240 格矿石的额外量 + 确定性 + 单调 |
| 精准采集 | I | 挖什么掉什么 | 玻璃掉玻璃（无附魔时掉空气） |
| 锋利 | V | 攻击伤害 +0.5·等级 | `damage_bonus` 与公式对拍 + 攻击链路取到它 |

不做"只有数值、没有效果"的装饰性附魔 —— 表里有而玩法里观测不到的东西，
就是在给后面的自己挖坑。

**耐久为什么用累积计数而不是概率**：概率版要么用 `random`（破坏可复现），
要么按使用次数哈希（同一把镐在不同次数上随机）。累积计数是**完全确定**的，
于是"耐久 III 的 251 耐久镐能挖 1004 下"可以**精确断言**，而不是"大约四倍"。
余数存在 `kernel.wear` 里并**进存档** —— 它是状态不是派生量（丢了会改变下一次磨损的时机）。

**互斥**：精准采集 × 时运（MC 同款）。理由很实在：两者同时生效会**互相抵消**
（精准采集把掉落换成方块本身，时运再多掉几个方块）。报价生成时按互斥筛，
`enchant_apply` 落账前**再筛一次**（报价是缓存过的，不能只信它）。

## 四、报价：确定性 + 绑定坐标

`offers(seed, x, y, z, 物品名, 工具种类, 玩家等级)` → 三档（成本 1/2/3 级）。

* **必须绑定坐标与物品**：否则"换个位置再点一下"就能刷出想要的属性；
* 同时它是**幂等**的：反复打开同一张台子看到的是同一批 ⇒ 这是**报价**，不是抽奖机；
* 随机流走 `recipes.rand01`（坐标哈希，与掉落数量**同一套**）—— 各写一份的后果是
  "掉落可复现、附魔报价不可复现"，而且两份迟早会漂开；
* 档位决定上限（`min(该附魔上限, 2·档 − 1)`）：第 1 档只能出 I，第 3 档才可能出 V；
* **稀有货抽签**：精准采集上限就是 I，于是它无论出现在第几档都只显示"I"——
  第 1 档（花 1 级）与第 2 档（花 2 级）看起来一模一样，报价就退化成"抽到废牌"。
  所以唯一等级的附魔**额外抽一次签**（1/2 概率才出现），台阶感才回得来。

**必须在台子前附魔**（`_enchant_table_pos()` 要射线打到附魔台）：没有这条，
"附魔"就是个飘在空中的菜单，玩家会问"那台子是干嘛的"。

## 五、附魔台的方块/贴图/配方

* 方块 id **81**（`MAX_ID` 80 → 81；有单测钉着"id 连续无空洞"）；

  —— demo 没有物品栏 GUI，合成出来的东西**只有在 hotbar 里才放得下去**。

## 六、顺手抓到的渲染静默失效（**本批最贵的一条**）

### 症状与误判

`examples/shot_enchant.py` 的第一版：附魔台在 2 格外是一团**平滑的紫色渐变**，
书脊与包边**完全看不见**；连旁边的石头平台、背景草地都是糊的。

第一反应是"我的贴图太细了"（Phase 3 的红石线就吃过这个亏）。但**棋盘格对照**
把这个猜想直接否掉了：把附魔台侧面换成 8×8 的黑白棋盘后，脸上出现的是
**一团模糊的白光** —— 采样把 16 个纹素平均成了两三个。这不是贴图的问题，是**采样**。

### 取证

`app.atlas.mag_filter` 读出来是 **9728（GL_NEAREST）** —— 属性说 NEAREST。
用 `glGetTexParameteriv` 直接问 GL：

```
GL 实际 mag = 9729 (GL_LINEAR)   min = 9729 (GL_LINEAR)
pyglet 属性 mag = 9728 (NEAREST) min = 9728 (NEAREST)
```

**属性说一套、GL 做一套。** 原因：`pyglet 2.1` 的 `Texture.min_filter` /
`mag_filter` 是**普通实例属性**（构造时用一次），不是 property —— 事后再赋值
只改 Python 那边的值，**不会调 `glTexParameteri`**。

于是从 Phase 0 起就注释着"⚠ **必须 NEAREST**：像素材质放大要用硬边，线性过滤会把它
糊成毛玻璃"，而实际一直在用创建时的默认 `GL_LINEAR`。**注释描述的意图从未生效。**

### 修法与取舍

```python
self.atlas.bind()                      # ⚠ 必须先绑：glTexParameteri 打的是"当前纹理"
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_NEAREST)
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_NEAREST)
```

顺带发现 `img.get_mipmapped_text()` 这个名字**在 pyglet 2.1 里不存在**
（叫 `get_mipmapped_texture`）⇒ 那个 `try` 一直在走"无 mipmap"分支。
改名之后 mip 链确实建起来了，但**用它渲染整屏全黑**（采样一张不完整的 mip 链，
GL 直接返回 0；把 MIN 改回 `GL_NEAREST` 即恢复）⇒ 本版**显式不做 mipmap**，
代价是远处贴图有轻微摩尔纹。这条写进代码注释，不静默降级。

**判据**：修完之后近景纹理**逐像素有硬边**（棋盘格对照从"一团白光"变成清晰的棋盘），
且三项验收全过；`shots/` 下所有目视图重生成了一遍。

> 副作用：`docs/phase3d_设计.md` §八 那张"逐像素差异"表是在 LINEAR 时代量的，
> 已按新图**重新测量并更新**（结论未变：retro 仍然**没有一个像素差 > 60**）。

## 七、另外三个坑（写 CLI 判据时踩到的）

1. **熔炉：一次给足 dt 会把燃料先烧完**。`furnace_step` 先扣燃料、燃料见底就停机
   ⇒ "烧完了"变成"没柴了"。判据里必须按"一炉时间 + 1s"给，别图省事给 999。
2. **相机落在整数格边界上，DDA 会把当前格判成旁边那一列**。俯视机位
   `pos = (cx+1.0, …, cz+1.0)` 起手就在体素角上，射线于是**擦着附魔台掉进石台**
   （准星报 `(129,32,129) stone`，而台子就在 `(128,33,128)`）。取个非整数偏移即可。
3. **地形台阶挡住视线**：附魔台正前方那一列比脚下高一格 ⇒ 射线先打到台阶 ⇒
   `_enchant_table_pos()` 返回 None ⇒ 报价与附魔**全部静默失败**，
   而错误信息却是"要先对着附魔台"（**症状离原因很远**）。
   ⇒ 判据里先清出观察走廊，并**断言"准星真的指到台子"**（测试前提不成立就当场报）。

## 九、这一批不做（已知边界）

* **不做青金石**：本仓没有青金石矿，为一件消耗品新开一条矿脉会改动世界生成
  （已有存档的矿脉分布会跟着变），不划算 ⇒ 代价只用**经验等级**。
* **没有书架增福、没有铁砧（合成/修复）、没有附魔书**：附魔只作用在**手持工具**上。
* **不做 mipmap**（§六：会黑屏），远处的摩尔纹是已知代价。
* **附魔按物品 id 存**（`{物品 id: {附魔名: 等级}}`）—— 沿用 `tool_durability`
  本来就有的假设"一个 id 只能有一把"。两把同种镐会共用附魔与耐久；
  要区分得先给工具加"实例 id"，那是另一件事。
