# mcclone3d 架构与阶段计划

> 本文是项目的**设计事实源**：说清"什么在哪、为什么这么分、下一阶段做什么"。
> 玩法约束与验收判据写在这里；实现细节写在代码注释里（每处都带"为什么"）。

## 一、三层分工（与引擎的约定一致）

| 层 | 在哪 | 职责 | 纪律 |
| --- | --- | --- | --- |
| **玩法内核** | `mcclone3d/kernel.py` | 玩家物理、挖/放、hotbar、库存、存档、自动机 | `inject = []`：**零 GL**，headless 可跑、可回放 |
| **数据与规则** | `blocks.py` `world.py` `mesh.py` `textures.py` | 方块表 / 体素世界 / 网格与 UV / 程序化贴图 | 纯逻辑或纯字节；**不 import pyglet.gl** |
| **表现** | `examples/mcclone3d.py` | 输入映射、网格上传、绘制 | 只做"把内核状态画出来"，**不发明玩法** |

这条分工的意义：**同一套玩法被两条路径驱动** ——
demo（人按键）与 `mcclone3d/cli.py` 的 headless 验收（脚本自动机）。
两边挂载用的是**同一份配置树** `configs/cordis.mcclone.yml`。

## 二、与 3dworld 引擎的接法（不改引擎一行）

引擎是另一个仓，本项目用它的三个**公开扩展点**接入：

```
_engine.setup()
  ├─ ensure_importable()   # 定位 world3d（本地检出 MC3D_ENGINE_ROOT **优先** → 否则 PyPI 包）
  ├─ register_service()    # registry.SERVICES['mcclone'] = mcclone3d.kernel:McCloneKernel
  └─ WORLD3D_CONFIGS=本仓 configs/   # 让引擎来本仓读配置树
host.tree.mount_tree(<本仓配置树>, want=('mcclone',))
  └─ ctx.mcclone  →  McCloneKernel 实例
```

`_engine.py` 只做这三件事，且**找不到引擎时响亮失败**（给出三条可操作的通路），
不做"静默降级"（降级会让问题在更远的地方炸）。

## 三、贴图：走引擎的 UV 投影与贴图规则

这是本版与旧 `blockworld`（每面一个图集格号）的**分水岭**：

```
face_uv_quad(face, x, y, z)          # mcclone3d/mesh.py
  u = (p · u_dir) * scale[0]         # 与引擎 texproj 同构（= Source texinfo 的 tv 向量）
  scale = 1 / (图集列数 × tile_size)  # 一格方块面 ⇒ 恰好跨一格图集格
  ↓
_atlas_uv(u, v, tile)                 # 取小数（= TexWrap.REPEAT）+ 映射进该贴图的矩形
```

三个**必须显式处理**的地方（都实测踩过，代码里有点名注释）：

1. **面的朝向**：引擎的轴向基不区分面的正负（`+x` 与 `-x` 同一套基），直接套用会让
   侧面贴图躺倒/镜像 ⇒ `FACE_BASIS` 直接存**每个面的 u/v 单位向量**，
   并用 `face_basis_normal()` 反算 `cross(u_dir,v_dir)` 与面法向对拍（单测穷举六面）。
2. **图集的 v 方向**：引擎口径是「数据 row0 在 GL 的 v 小侧」，而
   `textures.build_atlas()` 是**第 0 行写在上边** ⇒ `atlas_rect()` 里把**行号**翻转。
   *错法*：把面上的 v 取反（会让面的上下边取到同一行，贴图"对折"）。
3. **绕序**：`cross(c1−c0, c2−c0)` 必须等于面法向；顶/底面最容易写反
   （俯视图的"逆时针"在右手系里是 `(0,−1,0)`）。绕序反了开背面剔除会整片消失。

**密度口径**：`tile_size` = 一张贴图覆盖多少格。默认 `1.0`（每格一张图，MC 观感）。
调大 ⇒ 图放大到跨多格（近看单块细节）；实测调大后**远处会出现重采样摩尔纹**，
所以正式渲染用默认值，放大档只作为能力保留。

## 四、世界生成（确定性）

```
surface_height(x, z, seed, height)   # fBm 三倍频；基准与振幅**随世界高度缩放**
_column_block(...)                   # 一层一条规则，顺序即语义（见下）
```

* 顺序（**不能换**）：基岩 → 水/空气 → **地表那一格** → 土层 3 格 → 矿脉 → 石头。
  把"地表"排在"土层"之后 ⇒ 满地图没有草/沙/雪（`h >= h-3` 恒真）。
  把"矿脉"排在地表之前 ⇒ 地表会长出矿石。
* 一切由种子决定：**不用 `random`、不用 `hash()`**（后者带随机盐，同代码两次运行会生成不同世界）。
* 地面之上：树（`plant_trees`，走 `set_generated` ⇒ **不进玩家增量**）。

## 五、区块与网格

* 区块 16³；`ChunkedWorld.get/set` **自动跨区块**，所以边界上的面剔除是对的。
* `build_chunk_mesh(world, cx, cy, cz)` 只出可见面；`face_visible` 三档规则
  （不透明邻居挡死 / 同种透明块互相挡 / 其余画）。
* 改动经 `kernel._mark_dirty` 标记**本块 + 贴边邻块**；demo 按预算分帧上传
  （`_sync_meshes(limit=16)`）。**截图/验收前必须等 `meshes_ready()`** —— 早截会拍到
  "还没传完的世界"，那会被误读成"渲染丢了地形"。

### Phase 2-B 直接接这些现成接口

* **`kernel.hurt(n, cause)`** —— 受伤的唯一入口，生物攻击调它即可；
* **`kernel.spawn_drop(pos, item, n)`** —— 生物掉落物与方块掉落物同一条路径；
* **`kernel.cycle.is_night()` / `day_factor()`** —— 夜间刷新的判据，天然与光照同源；
* **`kernel.light.block(x,y,z)`** —— 敌对生物"躲进暗处/怕光"可以直接查它；
* **`Block.emissive`** —— 火把已经是光源，Phase 2-B 的"怪物怕火把"不用加字段。

## 七、已知边界与不做的事

* **世界是有限箱体**（默认 256×256×64，约 220 万方块）：无限地形需要区块流式加载，
  属 Phase 2。当前口径下"世界边界看得见"（世界外一律当空气）。
* **不含任何 Minecraft 官方素材**：贴图全部程序化生成（16×16 像素，逐字节确定性）。
  本项目是**机制致敬**，与原作无隶属关系、不声称任何商标。
* **不改引擎**：所有引擎侧差异（如 `MeshData.triangle_count` 对索引网格按 `//9` 少算 3 倍）
  只在本仓**记录 + 断言 + 回避**，不就地改 3dworld。

## 八、验收口径（每个阶段都要能跑）

```
python -m tests.run_all          # 285 项纯逻辑单测（零 GL）
python -m mcclone3d.cli          # 20 条 headless 验收（…/村庄/红石/tick 队列/AO）
python examples/mcclone3d.py --smoke 3       # 真窗口冒烟
python examples/shot_vista.py                # 目视：地貌 + 材质 + 选中框
python examples/shot_cave.py                 # 目视：洞口井 + 洞内矿石与火把照明
python examples/shot_weather.py              # 目视：雨天 / 雪天（同一机位，只差天气）
python examples/shot_village.py              # 目视：村庄（白天俯视整村 / 夜里灯火）
python examples/shot_redstone.py             # 目视：红石装置（通电前 / 通电后）
python examples/shot_inverter.py             # 目视：反相器（灯亮黄 ↔ 暗棕）
python examples/shot_ao.py                   # 目视：顶点级 AO（开/关）
```

判据不是"看起来对"，而是**可量化的比较**：同种子两次逐格相同、面数与逐格统计相符、
跳高与解析解对拍、自动机三种帧率结果一致、存档往返逐字段相等。
