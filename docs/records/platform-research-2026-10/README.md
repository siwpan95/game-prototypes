> **时点** 2026-10-16 ｜ **类** 记录（月份卷）｜ **范围** 为「朝更平台化方向延伸」做的四份联网调研
> **检索日期** 全部为 2026-10-16 ｜ **纪律** 每条结论带来源 URL；未找到可核查来源的地方如实标注

## 为什么有这一卷

用户第三项指令要求「结合联网搜索调研完成」。调研的**持久结论**已提炼进
[`../../spec/SPEC-101-platform-roadmap.md`](../../spec/SPEC-101-platform-roadmap.md)；
本卷保留完整证据（来源清单、检索日期、每条来源支撑哪个结论、哪些没查到），以便复核与更新。

## 四份报告

| 报告 | 主题 | 关键结论 |
| --- | --- | --- |
| [01-plugin-kernel.md](01-plugin-kernel.md) | 插件化内核选型 | Cordis 仍是 RC（维护密集、MIT、API 自陈未稳定）；Python 侧无等价物，`pluggy`/`stevedore`/entry-points 只解决「发现 + 钩子」，不解决「依赖声明 + 回滚」→ **不引入 Python 插件框架**，把生命周期放到协议层 |
| [02-platform-architecture.md](02-platform-architecture.md) | 微内核 / 内容治理 / 多语言 | 「什么进内核」判据＝被多个消费者共享且必须一致；事件总线只做广播，判定与结算走显式 RPC；内容包用双版本字段 + JSON Schema + 幂等迁移；`node:vm` 不是安全机制，进程边界才是 |
| [03-competitors.md](03-competitors.md) | 竞品与可复制机制 | 平台卖的是「每日节奏 + streak + 无剧透分享」闭环；每日一题**不需要后端**（按本地日期取题）；难度标定靠人工编辑，流程可抄、判断力不可抄 |
| [04-web-platform.md](04-web-platform.md) | Web 形态 / 编辑器 / 可访问性 | 视图模型 + 少量通用控件有成熟先例（JSON Forms），但必须做**原语白名单 + 未知原语 fail loud**；回合制选 POST + SSE；纯颜色玩法违反 WCAG SC 1.4.1，需给符号与文字 |

## 复核方式

每份报告的「来源清单」都标注了 URL、检索日期与支撑的结论。要更新某条结论，
重新检索该来源并**新写一条记录**说明修正了什么（本卷只追加，不改写）。

## 已知局限（如实登记）

- `web_fetch` 对部分站点（如 chiark、维基）持续失败，相关结论改用 `web_search` 结果交叉引用，报告内已把二手来源单列。
- 明确标注「未找到可核查来源」的项：Python 侧 schema 校验器选型、自动化无障碍工具（axe 类）、
  广告类收益数据（ARPDAU/eCPM）、「何时开放 mod 支持」的可操作判据、文字解谜类开源关卡编辑器。
