# Phase 3 设计稿：红石级机制

> 范围：**信号闭环（红石线 / 拉杆 / 按钮 / 红石火把 / 红石灯）+ 中继器 + 铁门 + 活塞**。
> 用户拍板的三条：四项全做（含中继器）、活塞**连锁推 12 格**、活塞朝向**按视线方向**。
>
> 这份稿的重点有四个，都是"看起来不难、做起来出事"的地方：
> **① 有向元件为什么必须真的写方向**（§五 自锁 bug，本稿最重要的一节）；
> **② 活塞的原子性**（§六，含一个 Python `while-else` 陷阱）；
> **③ 两格方块的"输入要合看"**（§七 门的振荡）；
> **④ 扁平盒渲染的三条坑**（§十，其中一条把整个世界染成了红色）。

---

## 一、模块与挂点

| 文件 | 角色 |
| --- | --- |
| `redstone.py` | **信号引擎**：强度场、网络收集、传播、输出判定、活塞/门的动作 |
| `blocks.py` | 25 个红石方块 id（含 6 朝向活塞 × 2 态、4 朝向中继器 × 2 态）+ 物品别名表 + `place_cells` |
| `mesh.py` | 扁平盒（红石线）+ **信号强度顶点色** |
| `kernel.py` | `use()`（右键交互）/ `place()` 多格与朝向 / `_post_step` 驱动 / 挖掘联动 |
| `textures.py` | 17 张程序化贴图（`ATLAS_COLS` 6 → 8） |

内核挂点与已有的三套系统同构：

* **光照**（Phase 2-A）：`on_change` 回调直接接 `_mark_dirty` ⇒ 红石改方块时网格与光照自动失效。
  红石灯点亮时正是靠这条让光照引擎知道"这里多了个光源"（灯是 `emissive=1.0`）。
* **水流**（Phase 2-C）：`_post_step` 里按预算推进；世界重建（`reset`/`load`）时信号场必须重建。
* **刷怪/生存**：无耦合。

## 二、信号**不进存档**，但状态进存档

红石线不存在 16 个 id，强度由**布局**算出来（与光照同口径）：

* 存档只存"玩家放了什么方块"。**拉杆开/关、门开/关、活塞推出/收回都是方块 id**
  ⇒ 它们自然进档；
* 信号强度、灯亮、被活塞推走的方块位置都是**派生状态** ⇒ 不进档，读档后按布局重算。

代价（必须写明）：**被活塞推走的方块不在存档里**。读档后活塞若仍通电会再推一次得到
同样结果；若玩家把活塞拆了，被推的方块会"回到"存档记录的位置（因为它没被记录移动过）。

## 三、"一个物品 ↔ 多个方块状态"：别名表

玩家手里只有"拉杆"这一件东西，而方块表里有 `lever_off` / `lever_on`。
`blocks.BLOCK_ITEM_ALIAS` 把状态名映射回物品名，`recipes.as_item()` 查不到同名物品时查它。

* 好处：挖掉**开着的**拉杆也掉拉杆（否则会"什么都不掉"）；
* 代价：`test_items` 里"方块名必须等于物品名"这条断言必须放宽为
  "**要么同名同 id，要么别名表里显式登记**"（这是真需求确认过的改动）。

放置时的"多格与朝向"收口在 `blocks.place_cells()`：普通方块一格、门竖着两格、
活塞/中继器按**视线方向**选朝向的 id。`kernel.place()` 只负责逐格检查空位。

## 四、信号引擎：按**网络**重算，不是按空间盒子

光照用"空间盒子 + halo"（光向各方向衰减）。红石不一样：它只在**连通的元件网络**上走。

```
从变化点出发 → 找连通的元件格（线 / 中继器 / 电源 / 输出）→ 重算这批格
```

好处是**精确**：长线路（带中继器）一次算对，不会被"半径 16 的盒子"在中间截断。
代价是网络可能很大 ⇒ `NETWORK_CAP` 护栏（超了抛 `RedstoneOverflow`，绝不静默截断）。

**固定点迭代**：中继器 → 线 → 中继器 这样的链要逐轮点亮，所以每轮"清空 → 传播 → 切输出"，
输出有变化就再来一轮（状态有限 ⇒ 必然收敛；`MAX_ITER=8` 只是护栏）。

三条传播规则（都能穷举测试）：

1. **只有红石线继续传导**（每格 −1）；**电源给紧邻的线满 15**（拉杆像"强充能"了那一格）；
2. 输出的输入 = **六邻里最大的信号**（≥1 就触发）；灯/门/活塞**不导电**；
3. 中继器**有向**：只看背面、只给正面（见下一节）。

## 五、有向元件必须真的写方向 —— 中继器的**自锁 bug**（本稿最重要）

初版把中继器做成"无向放大器"（六邻都吃、六邻都吐）。结果：

* 它**自己给自己供电** —— ON 之后给邻居线 15，那根线又回过头来让它保持 ON；
* 表现：**拉杆关掉后中继器仍然亮着**（断电也不灭）；
* 更糟的是它会把这个自环藏起来：单看"通电 ⇒ 亮"的用例是**通过**的。

修法不是打补丁，而是**改成 MC 的真实语义**：中继器是**有向**的（背面输入、正面输出）。

* 4 个水平朝向 × 2 状态 = 8 个 id；
* 传播时**只给正面那一格**供 15；
* 判定时**只看背面那一格**（`repeater_face`）。

⇒ 自环在结构上消失（它再也看不到自己供的电），链条仍然成立（A 的正面 → 线 → B 的背面）。

**教训**：无向的"放大器"在图上必然产生自环。凡是"输入输出"语义的元件，
方向不是可选优化，而是**正确性的一部分**。

## 六、活塞：原子性 + 一个 `while-else` 陷阱

推方块的三条口径：

1. **连锁推最多 `PUSH_LIMIT=12` 格**（用户拍板）；
2. **原子性**：先"收集整条链 + 确认最远端前面是空气"，**再**动手。
   边判边移会在"推到一半发现推不动"时留下被拉长的方块堆；
3. **推不动就整体不动**（前面是基岩 / 红石元件 / 超过 12 格 ⇒ 一格都不许动）。

⚠ 实测踩到的 Python 陷阱：初版写成

```python
while len(chain) < PUSH_LIMIT:
    ...append...
else:
    return 0        # 以为这是"超过上限"
```

`while-else` 在**循环条件变假而正常结束**时也会执行 —— 正好 12 个方块时循环是正常结束的
⇒ 被当成超限 ⇒ **12 个推不动、13 个反而"判据正确"**，看着像上限设错了。
现在写成 `while True` + 显式 `if len(chain) >= PUSH_LIMIT: return 0`。

另一条：**收回只删臂**（普通活塞不拉回），被推的方块留在新位置。
判定"该删的是臂"靠 `PISTON_ARM` 这个 id（不是"前方那格"——那里可能是玩家放的东西）。

## 七、两格方块：**输入也要合看**（门的振荡）

铁门占上下两格。初版让门的输入只看"自己那一格"的六邻：

* 下半格挨着红石线 ⇒ 判"有电" ⇒ 开门；
* 上半格四周只有门与空气 ⇒ 判"没电" ⇒ 关门；
* 两者在同一轮里轮流生效 ⇒ **振荡**（实测一次重算 `switched=32`，门最终是关的）。

修法：`_door_powered()` 把两格**合起来看**（任一半格有电就算有电）。
"两格一体的东西，读输入要一起读" —— 与"挖门要一起挖"是同一条道理的两种表现。

## 八、渲染：扁平盒 + 信号强度顶点色

* **扁平盒**：红石线画成 1/8 格高的薄盒（`mesh.THIN_BLOCKS` + `_append_face(height=...)`）；
  整方块高的"红砖"既挡路又完全不像"地上的线"。
* **信号顶点色**：`build_chunk_mesh(power_of=...)` 把信号强度乘进顶点色
  （0 → 35% 亮度，15 → 100%）⇒ **一条线亮到哪一格为止是看得见的**。
  与光照顶点色同一套机制（`light_of`），不传就是 Phase 1 的行为（逐字节相同）。

## 十、扁平盒渲染踩到的三条坑

1. **贴图太细**：红石线的十字贴图起初只有 2px 宽（1/8 格），8 格开外只有一两个像素
   ⇒ 截图里"整条线看不见"。加粗到 4px（1/4 格）+ 中心亮块；
2. **深度精度**：1/16 格高的薄盒在 9 格开外会被**地面的顶面**吃掉
   （只高 0.0625 格，远处两个面抢同一段深度缓冲）⇒ 主线整条消失、只有近处的支线露出来。
   改成 1/8 格；
3. **UV 错位（最贵的一条）**：`mesh.atlas_rect` 原先拿引擎 `Atlas.rect()` 给的 v0
   **反推行号**（`int(round(v0 * rows))`）。引擎按"每格 1/cols"归一化，
   反推却用 `rows` —— 图集不是正方形时就取到错的行。`ATLAS_COLS` 从 6 提到 8 之后，
   **整个世界都采样到了红石线/红石灯的贴图**（截图里地形一片暗红）。
   现在改成"行号自己算"（`textures.TILE_INDEX` + `LAYOUT.uv_rect`），只保留一次必要的 v 翻转。

## 十一、不做（刻意）

* **中继器没有延迟**（MC 有 0.1s/档）：我们的红石一个 tick 内算到固定点，没有"时钟"概念。
  真要做时钟/脉冲，得引入**元件 tick 队列**，那是另一批的活；
* **比较器 / 侦测器 / 红石线爬墙**（我们只有平面四向 + 上下）；
* 红石线的**连接形状**不随邻居变化（统一用"十字"贴图，MC 会按连接方向变形）；
* 中继器的 4 个朝向**共用同一张贴图**（朝向的正确性在功能里，不靠贴图区分）；
* 红石信号**不能用"红石粉"续接**（我们不做掉落物形态的红石）。
