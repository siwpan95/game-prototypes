# Phase 2-B 设计稿：生物（被动游荡/逃离 + 敌对夜间刷新）

> 分工与前两期一致：**数据与 AI 都是纯逻辑（零 GL）**，表现层只消费数值。
> 这份稿的重点不是"加了三种生物"，而是三件事：**为什么不做 A\***、
> `MobContext` 为什么刻意收窄、以及一串**不报错但世界看着是死的**类 bug
> （状态机没有出口、推开是死代码、接错了受伤入口）—— 这类 bug 不会红，只会让
> 守卫判定"看起来全绿"。

## 一、两个模块 + 内核挂点

| 模块 | 职责 | 关键取舍 |
| --- | --- | --- |
| `mobs.py` | 生物表 `MobKind`（**只有数据**）+ 实体 `Mob` | **不引 ECS**（一次最多几百只，间接层抵不过收益）；盒模型 `parts` 是数据 ⇒ 加一种生物不改渲染 |
| `ai.py` | 状态机 + **贪心寻路（带跳台阶）** + 与方块的碰撞 | 不做 A\*（理由见 §二） |
| `kernel.py` | `mobs` 列表、`update_mobs`、`spawn_mob` / `hit_mob` / `attack`、生物打玩家的入口 | 攻击调 `damage_player_from_mob`（内部走 `hurt` —— 掉血仍然只有这一个入口）；掉落走 `spawn_drop`（与方块掉落同一条路） |

阶段计划里点名的现成接口全部接上，没有为 2-B 加新机制：
`kernel.hurt`（受伤唯一入口）、`kernel.spawn_drop`（掉落唯一路径）、
`cycle.is_night()/day_factor()`（刷新判据与光照同源）、`light.block/sky`
（"只在暗处刷"、"白天露天自燃"）、`Block.emissive`（火把直接就是光源，
"怪物怕火把"不用加字段 —— 本版没做怕火把，留白）。

## 二、为什么不做 A\*

本项目的"世界理解"只有方块，而"绕过复杂迷宫"对生物体验的边际收益很低，
却要把寻路做成独立子系统（代价高、调参难、还要处理目标移动后的重算）。
所以做**贪心 + 跳台阶**，心智模型说死：

* 每帧朝目标方向走，**分轴移动**（贴墙滑行自然成立，与玩家 `_move_axis` 同思路）；
* 水平被挡住时**试着往上跳一格**（能上 1 格台阶、能翻栅栏）；
* 前方两格高都挡住 ⇒ 左右各试 45°，都不行就停下（追击时改为起跳）。

**会绕开单格障碍、会上台阶，但不会绕迷宫 —— 说到做到，不假装更强。**
性能口径：一次 `step_mob` 对每只生物是常数工作量（几次方块查询），
没有全局扫描、没有寻路搜索树；判据 **300 只每帧 < 8ms**，实测 **2.56ms**
（`cli --only mobs` 末行）。

## 三、AI 状态机（四态，迁移全部有出处）

```
idle ──age>0.5──▶ wander ◀──passive 被打── flee ──6s──▶ wander
                     ▲                                          ▲
        hostile 且 dist≤sight │                                  │
                     └────── chase ────dist>sight×1.4────────────┘
                                （敌对被打也立刻进 chase）
```

* **追丢用 `sight×1.4`**（宽于进入阈值）：防止生物在 sight 边界上抖动切换；
* **游荡方向** = `age + id` 的确定性伪随机（不用 `random`、不用 `hash()`）——
  同一条时间线回放结果一致，可对拍；`id` 是全局顺序号，所以**回放的前提是
  新进程 + 同脚本**（单测里复位 `Mob._next_id` 来构造"同一条时间线"）；
* **被动的待机生物必须自己开始游荡**（§五.3 记着这条坑）。

## 四、与世界的三条纪律（都是"想破坏必须先改设计"的显式决定）

1. **`MobContext` 刻意收窄**：AI 只能看方块、光、时间和玩家位置。
   为什么不直接传 kernel：AI 一旦能摸到内核的全部接口，就会有人从 AI 里
   `dig()/place()`，"生物能改世界"这种设计意外会悄悄出现。
   现在想加这种能力必须**先改这个类**。
2. **生物打玩家必须走 `damage_player_from_mob`**，不能接裸 `hurt`：
   它除了掉血还管**计数与击退**（§五.6 记着接错的症状）。
3. **生物死亡掉落走 `spawn_drop`**，与方块掉落同一条路径；
   **白天烧死不给掉落**（自燃是环境伤害，不是"被打死"）。

## 五、实测踩过的坑（留档，按发现顺序）

1. **落地吸附判据**：先前写 `if pos - floor(pos) < 0.5: pos = floor(pos)` ⇒
   y=18.494 这种"离地面 0.506 格"的位置**永远悬空**、`on_ground` 恒 False，
   所有"站稳才允许"的动作全部失效。正确判据是**往下被挡 ⇒ 贴到挡它的那一格顶上**。
2. **判"站在地上"只看脚下**：拿 `_body_blocked`（它在 `y+0.05` 采样）判能不能往下落，
   会把自己脚下的方块算成障碍 ⇒ 羊停在 y=13.99 不动。拆出 `_standing_on`。
3. **状态机少了出口**：漏了 idle→wander 的迁移 ⇒ 新刷的生物永远站在原地。
   不报错、不飘红，**但世界看着是死的**。单测 `t_idle_to_wander` 钉住。
4. **重合推不开是死代码**：生物与玩家完全重合时 `_heading()` 因 `n < 1e-6`
   返回 `(0,0)` ⇒ `wx=wz=0` ⇒ 既不移动、也永远走不到推开那一步 ⇒
   距离恒 0，而且这一帧照样白打玩家。`_keep_distance_from_player` 里
   `d < 1e-4` 的兜底因此永远执行不到。修法：推开那一步必须在
   `if wx or wz:` **之外**。
5. **`mobs=False` 与 `spawn_mob` 共用一个开关** ⇒ 关自动刷怪之后手动放生物
   静默返回 None，测试拿到 None 才在下一行炸 `AttributeError`
   （报错点离根因很远）。现在 `mobs=False` 只管自动刷怪，手动放是显式意图。
6. **接裸 `hurt`**：症状是"玩家被打了但一点反馈都没有、
   `mob_stats['player_hits']` 恒为 0" —— 守卫判定看起来全绿，
   **因为它只查了血量**。
7. **刷怪用 `surface_at + 1`** ⇒ 把生物埋进沙里（`surface_at(38,32)` 返回 12
   而沙堆到 13），症状"生物一动不动、`_body_blocked` 恒真"。
   改成 `ground_below`：自上而下找"脚下实心 + 身位空"，与玩家出生同一套判据。
8. **判据被时间污染**：测"上台阶/追击"不冻结昼夜 ⇒ 僵尸走到一半被晒死，
   判据变成"能不能在 2 秒内追上"（第一版就假绿过）。为此加两个配置口：
   `time_phase`（直接跳时刻）+ `time_paused`（冻结昼夜）。
9. **台阶判据看终点**会把"真的上去了"判成失败：上了台阶的生物会继续朝玩家走、
   **走下坡回到原位**。判据改看**过程峰值**。
10. **`attack()` 文档承诺"视线前方没有方块挡住"但没实现**（隔墙抿人）——
    本轮补上 `raycast` 前置检查 + 回归测试 `t_attack_blocked_by_wall`。
    与挖方块同口径：先问到墙，这一下就什么都不会发生。
11. **demo 里生物渲染从来没真正跑过**：`_sync_mob_verts` 用了 `mesh.build_mob_mesh`
    但 demo 没 import `mesh` —— 第一帧 on_draw 就 `NameError`。前一版写完只跑了
    headless（零 GL），**渲染路径一次都没执行**。本轮跑截图脚本时当场炸出来
    （`name 'mesh' is not defined`）。教训与 Phase 0 的"截图/验收前必须等
    `meshes_ready()`"同源：**GL 路径要有自己的冒烟**，不能只靠 headless 全绿。
12. **光照被烘进生物顶点色**：`build_mob_mesh(light_level=15, night=0)` 的默认值
    把"满亮正午"烘进按种类缓存的网格 ⇒ 夜里和洞里的生物一身死白
    （2-A 刚修过同类的"天空色写死"，截图一眼穿帮）。改成顶点色只烘
    **部件色 × 面亮度**，光照走逐实例 `u_light` uniform（`light_color(1.0, lvl, night)`，
    取该生物脚底那格的有效光，与区块网格的 `face_light` 同口径）。
13. **`light_color` 第一参是标量不是三元组**（`_append_face` 传的一直是 `bright`）——
    传 `(1,1,1)` 会炸 `can't multiply sequence by non-int`。命名误导，调用处已点注。

## 六、刷怪判据（纯函数 + 周期批量）

* `spawn_allowed(kind, block_light, sky, night)`：**敌对** = `max(方块光, 天光折算)
  ≤ spawn_light_max`（僵尸 7 ⇒ 只在暗处/夜里出现）；**被动**恒可。
  纯函数 ⇒ 单测 16×16×2 逐条穷举对拍。
* 周期 **4s** 一批、每批最多 2 只；刷新用**确定性 rng**（`seed ^ 0x5EED`）——
  刷怪位置可复现，录制/回放才对得上。
* 刷新点在玩家周围 **16~48 格**（别刷在脸上），高度用 `ground_below`（见 §五.7）。
* 上限 **240 只**（`MAX_MOBS`，性能护栏）；离玩家 **96 格**自动消失
  （`DESPAWN_DIST`，防累积）；掉出世界（`y < -4`）判死移除。

## 七、存档口径：**v3 不变，生物不进存档**

与光照"不存"是两个不同的理由，都记录在案：

* 光照不存，是因为它**能由方块与时刻完全重算**（存了反而会出现
  "存档里的光照与方块不一致"这种不可自愈的脏数据）；
* 生物不存，是因为它是**动态状态**（位置/血量/AI 状态都不能由世界重算），
  而选择是**不存**：读档后 4 秒内会自然重刷一批，玩家侧无感；
  存了则要处理"未知生物名"的读档校验、逐字段往返测试、
  以及"存了的牛会不会因为在旧地形位置而卡进玩家新砌的墙里"这类边界。

代价说清楚：**存档/读档的瞬间，世界里的生物全部消失**（掉落物不受影响，
它们在 v2 就随存档走）。Phase 3 若要做"家畜圈养"这类依赖实体存续的玩法，
再升 **v4**（加 `mobs` 字段，只增不改语义，读档继续吃 v1/v2/v3）。

## 八、渲染：生物的长相是**数据**

`MobKind.parts` = `((相对位置, 尺寸, 颜色), ...)`，渲染端
（`mesh.build_mob_mesh`）把它们当**六个面的盒子**画（复用方块那套 UV 投影）：

* 每种生物**只上传一份网格**，实例靠 `u_origin` uniform 平移 ⇒ 40 只羊
  只占一份网格的显存；新增生物不改渲染代码；
* 部件尺寸必须是**整数格**：网格按整数角落生成（UV 投影要求跨格连续），
  0.6 这种尺寸会被 `round` 成 0 厚度 ⇒ 部件消失。块状感是与方块世界一致的
  刻意选择；
* `MobKind.height` 必须与盒模型总高一致（僵尸 `height=5.0` ↔ 人形模型 5 格），
  否则碰撞与渲染对不上；
* 受击闪烁 = 顶点色乘一层红（`u_tint`），不引第二套材质；
**不做朝向旋转**：1×1 的部件转不转肉眼看不出，加矩阵 uniform 会让每次
draw 都多算一遍 —— 这条取舍是故意的，不是漏了。

* 单测 **13 模块 181 项**（新增 `test_mobs` 9 项 + `test_ai` 31 项 +
  `test_mesh` 生物网格 4 项）；

  游荡 4.5 格 / 整数站立 / 上 1 格峰值 19.0 与 2 格挡死 / 追击最近 0.75 /
  命中 13 次且冷却 1.0s / 间距 ≥0.75 / 死亡掉落 / **300 只每帧 2.56ms**；
* **目视**：`python examples/shot_mobs.py` 同一机位拍两张（白天羊猪 / 午夜僵尸），
  日志带每种生物的数量与所在格有效光（夜里实测 3 ⇒ `light_scale` ≈ 0.23，
  压暗但轮廓可辨，不是全黑）；午夜张同时看到星空；
* 存档：v3 不变，v1/v2/v3 老档照常可读（测试逐版本断言）。

## 十、不做（这一版刻意不碰）

* **A\* 寻路 / 绕迷宫**（§二）；
* **生物进水游泳**：水不算固体，生物直接落过水（与世界生成的"水"解耦，
  要做得连玩家一起改，属表现+物理联动）；
* **怕火把**（`Block.emissive` 已够接，但本版没做"怪物躲光源"的 AI）；
* **生物互伤/生物间社会行为**（狼吃羊之类）：`MobContext` 现在只有玩家一个
  "他者"，加世界列表要先改那个类 —— 那是显式设计决定，不是顺手加；
* **实体存档**（§七，留 Phase 3 的 v4）。
