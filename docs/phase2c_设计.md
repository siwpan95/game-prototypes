# Phase 2-C 设计稿：洞穴 + 矿脉分层 + 水流动 + 天气

> 范围：**第一批**（洞穴空腔 + 自然洞口 + 矿脉按深度分层）、
> **第二批**（水流动 + 天气）。村庄与结构留在 2-C 余批。
> 这份稿的重点有两个：一是**三级洞穴场**为什么要预计算 + 块级剪枝（实测数据），
> 二是**加洞穴把 Phase 2-A 的光照引擎顶出一个阻塞级 bug** —— 那一节是本稿最有用的部分。
> 第二批的重点则是**水流模型的两次推翻**（CA 不收敛 → 垂直灌注，§九）。

## 一、三个模块 + 内核挂点

| 模块 | 职责 | 关键取舍 |
| --- | --- | --- |
| `caves.py`（新） | `CaveField` 三级洞穴场 + `TunnelIndex` worm 隧道 + 三条护栏 | **预计算 + 块级剪枝**（§三）；不逐格做 3D fBm |
| `world.py` | `_column_block` 接入洞穴（矿脉之前）；`ORE_BANDS` 按深度分层 | 约束写在判据里，不靠调用顺序（沿用 Phase 0 的纪律） |
| `blocks/items/recipes/textures` | 金/钻石矿石 + 材料 + 掉落 + 程序化贴图 | **id 只追加**（矿石 20/21、材料追加在 `_defs()` 末尾） |

## 二、洞穴模型：cheese 空腔 + worm 隧道

| 手段 | 做什么 | 为什么 |
| --- | --- | --- |
| **cheese 空腔** | 三级噪声场超阈值就挖空 | "大空腔 + 块状边界"，与方块世界气质一致 |
| **worm 隧道** | 从地下向上游走的管状通道（球半径 1.9），**只在到达洞顶层时补一个"地表窗口"球** | 噪声挖穿地表是随机的、玩家找不到；worm 保证**必有洞口且位置可复现** |

护栏（三条，写在判据里）：**基岩与 y=1 不挖** / **表土保底 3 格**（洞顶有岩层）/
**水下地形整列不挖**（本项目没有流体系统，洞里进水没法修）。
worm 是唯一允许打穿表土的东西，但它也遵守"水下地形不挖"。

## 三、性能：为什么要三级场 + 块级剪枝（实测）

预算：默认世界 256×256×64，地下候选带 **1.83M 格**（实测平均 28 格/列）。

| # | 做法 | 实测 | 根因 |
| --- | --- | --- | --- |
| 1 | 逐格一次三线性插值的 3D 值噪声 | **+3.3s（4.82→8.11s，+68%）** | 每格 8 次哈希 + 8 次数组索引 + 插值 |
| 2 | 改成"预建 `CaveField` 实例，消掉每格的模块导入" | **8.11→8.10s，一分钱没省** | ⚠ **猜测错了**：真正的开销是每格的哈希与插值，不是导入 |
| 3 | cProfile 定位 | `_hash01` **187 万次**占 tottime **1.9s**；`is_cave` **2.65µs/次** ⇒ 全图 **+4.85s** | 实锤 |
| 4 | **三级场（粗格 8×4×8 / 块级中频 / 逐格细噪）+ 块级剪枝** | 剪枝率 **70~79%**；`is_cave` **0.75µs**；`generate()` **5.79s（+20%）** | 粗格离阈值太远的整块 256 格**连细哈希都不算** |

最终口径：阈值 **0.75 − 0.03×(1−y/sea)**（越深越低 ⇒ 越深越密），
64 高世界实测挖空 **10.0%**（浅层档最少、中层最多，方向正确）。

⚠ **别改 `_hash01` 的算法**：存档只存「种子 + 编辑增量」，地形/矿脉/洞穴
全部由它重算 —— 改哈希会让老存档里的玩家建筑浮空或埋进石头。
只能做**行为等价**的优化（把函数体内的 `import math` 提到模块级）。

## 四、矿脉分层（2-C 点名的另一半）

`ORE_BANDS = (煤 40 / 铁 28 / 金 16 / 钻石 8)`，深度上限**随世界高度等比缩放**
（基准 64 高）—— 与 `surface_height`/`sea_level` 同一套缩放纪律，写死绝对值会让
32 高的测试世界里钻石层挤成 3 格。

两条实现要点，都踩过：

1. **深度只决定"能不能出现"，同深度内各矿种按概率分段**。
   初版写成"从上往下第一个满足上限的带胜出" ⇒ y=27 永远只能是煤，
   铁实际只落在 y<16 —— **分层名存实亡**。改后（64 高实测）：
   煤 94383 > 铁 64899 > 金 18261 > 钻石 3437 ✓ 单调递减。
2. **一次哈希定矿种**（把 `[0,1)` 按各带概率切段），不是每带一次哈希：
   深层格平均 2.64 个候选带 ⇒ 初版 118 万次哈希；改后每格 1 次
   （`generate()` 从 8.1s 回到 5.9s）。

图集：加两张矿石贴图 ⇒ `ATLAS_COLS` 5→**6**（第 6 行会落到图集外面，
这是 `ATLAS_SIZE = ATLAS_COLS × TILE` 正方形假设的必然要求）。

## 五、加洞穴顶出来的**阻塞级 bug**（本批最重要的一节）

### 光照 BFS 没有盒子边界 ⇒ demo 直接起不来

症状：`python examples/mcclone3d.py --smoke 3` 抛
`LightOverflow: 光照扩散超出上限（sky）：已访问 1137538 格 > 400000`。

根因：`_spread_from` 的 BFS 用 `world_get` 扩散时**没有范围限制**。
世界没有洞穴时无所谓（地下全实心，扩散几步就撞墙停）；**一旦有洞穴**，
天光顺着洞口灌进整个洞穴系统 —— 每写一次值就再扩散一轮，访问量冲到 113 万，
而且它还是**错的**：洞里被灌成 level 14 的"全亮"。

修法（按 `relight_chunk` 文档早就写着的"只在本区块内扩散"补上实现）：
`_spread_from` 增加 `box` 参数，`relight_chunk` / `relight_around` 都传盒。
修后：全图逐区块 relight 通过；洞内黑 4231 / 亮 1645（亮的只在洞口附近，正确）。

## 六、其余实测踩坑（都留了判据）

1. **`COARSE` 的尺度被当成插值权重**：`c + (c1-c)*8` 把 density 值域放大到
   ±316 ⇒ 阈值从 0.585 调到 0.75 挖空比例都是 49.5%（怎么调都没用）。
   正确：粗格场只存**纯节点值**，插值统一在查询时做。
2. **阈值方向写反**：写成 `+0.02×(sea-y)/sea` ⇒ 深处阈值 0.679 > 浅处 0.660，
   实际成了"越浅越密"。单测 `t_threshold_deeper_denser` 抓到的。
3. **worm 的球打不穿地表**：半径 1.9 的球在**整数格**判定下只到 ±1 格
   （`dy=2` 时距离²=4 > 3.61），球心停在"离地表 3 格"就够不到地表格。
   修法：到达洞顶层时**额外补一个球心在 `h-1` 的球**，正好覆盖 `h-2/h-1/h`
   —— 表土保底 3 格与"打穿地表"两件事同时成立。
4. **`is_cave` 重构时丢了一条护栏**：重构把"水下地形整列不挖"弄丢了，
   于是岸边地形（h ≤ sea+1）下面被挖空。单测 `t_underwater_column_untouched` 抓到。
5. **洞口的"可达"判据一度用海平面挡天空**：洞口在 y≈34 而海平面只有 30，
   用 `sea` 会把洞口那几层一起挡掉 ⇒ 明明连通的隧道被判成不可达。
   正确：按**该列自己的地表高度**挡天空。

# 第二批：水流动 + 天气

## 九、水流：**两次推翻**才落地的模型（本批最有用的部分）

### 第一版：MC 式 level 元自动机（CA）—— **永不收敛**

按 MC 的口径写：源 + level 1..7，下落 / 水平扩散 / `level+1` 衰减 / 7 级干涸，
每 tick 只处理"活跃格"并带预算。在真实地形上**失败得很彻底**：

```
挖穿海床后连跑 3000 tick ⇒ 洞内水量卡在 6/343，active 永远非空
（水在洞底"冲刷 → 干涸 → 再冲刷"，逐 tick 交替 y=21/22）
```

三次尝试的中间修复，都只是把"不收敛"换了个样子：

| # | 修补 | 结果 |
| --- | --- | --- |
| 1 | 源的供水被 `continue` 跳过 ⇒ 改"源只供水、不移动" | 水终于会灌进洞了，但仍在洞底来回冲 |
| 2 | 水"下落"不允许进入水格 ⇒ 改 `allow_water=True`（水柱能合并） | 水柱连续了，但洞底依旧不收敛 |
| 3 | 让 level 1 的水"无处可去就停住"（MC 的 falling water） | 仍然不收敛：无限水源持续补水，而洞底永远在"往旁边流" |

**根因**（三条同时成立才炸）：① 海的**无限水源**持续补水；② 下落与水平流互斥，
洞底的水永远在"往旁边流"与"被上面填回来"之间摆；③ CA 里**没有"水面"概念**，
找不到稳定态。

### 第二版（落地）：**垂直灌注** —— 一次性、可预测、不震荡

```
玩家改动 (x,y,z) ⇒ 记一个扰动点
每 0.05s（`FLUID_INTERVAL`）取一个扰动点：
  从该点**向上找同列最近的水（源或已有水）**；找到就沿垂直方向灌到非空气处为止
```

实测：挖穿海床立刻灌满整根水柱（**7 格，一个 tick 完成**），
200 tick 后水量不变、`active` 清空 —— **完全静止**。

为什么这个简化是**合理的**（不是偷懒）：

* 本项目**没有水桶**（玩家不能主动倒水），水只能由"改地形"驱动 ⇒
  一次挖 = 一次灌注，**不需要每帧演化**；
* 玩家挖一整条隧道会**逐格触发** ⇒ 水跟着挖通路径一路灌进去，
  这正是"洞穴与海打通"要的观感；
* 无迭代 ⇒ 无震荡、可测试、性能可预测（`TICK_BUDGET` 只是防呆）。

### 水与洞穴："打通"靠流体，**不改生成**

第一批的护栏是"**水下地形整列不挖**"（洞里不能进水）——第二批**没有动它**：
洞初始仍然无水，**玩家挖穿海层才进水**（与 MC 同款）。
`caves.py` 与 `fluid.py` 因此完全解耦：前者管"地形长什么样"，后者管"水往哪流"。

### 水流的状态纪律（与光照同口径）

`levels`（哪些格是流动水）**可由「源 + 方块」完全重算** ⇒ **不进存档**（仍是 v3）。
⚠ 所以灌注必须走 `world.set_generated`（不记增量）—— 用 `world.set` 会把水写进存档。
读档时洞还在增量里、水不在 ⇒ `repour_all()` 重放一遍玩家的改动点即可
（实测 1 万条 edits ≈ 0.3s，比"扫全图找水源"便宜两个数量级）。

## 十、天气：**时刻的纯函数**，不进存档

与 `sun.py` 同一套纪律：天气 = `f(时刻, 种子)`，不随机、不推进、不进存档。
每 `WEATHER_SLOT`（90s）一段，段内强度按 `sin` 平滑起落（**不突变** ——
突变的天光看起来像 bug）；约 45% 的时段是晴。

| 天气 | 判据 | 影响 |
| --- | --- | --- |
| 晴 | 强度 < 0.15 | 天光满档 |
| 雨 | 强度 ≥ 0.15 且 `day_factor ≥ 0.45` | **天光 ×0.72** |
| 雪 | 强度 ≥ 0.15 且 `day_factor < 0.45` | **天光 ×0.80**（比雨亮） |

"下雪还是下雨"用**昼夜**分流（夜里暗 ⇒ 雪），不另设温度系统。
天光乘子只加在**一处**（`kernel.day_factor()`）⇒ 光照、天空色、
生物自燃判据看到的都是同一个值，不会出现"天还亮着但地面按雨天暗了"的分裂。

表现层：屏幕空间降水粒子（雨=竖线，雪=短粒+摆动），复用 HUD 的 `ui_prog`。

## 十一、第二批的实测踩坑

1. **光源不供水**：源格被 `step` 直接 `continue` ⇒ 挖穿海床后洞里一格水都没有。
   改成"源只供水（向下填）、不移动"。
2. **`can_enter` 把"已有水的格"当障碍** ⇒ 水柱停在半空（洞里变成"一格水一格空"
   的稳定态）。下落要 `allow_water=True`（水柱能合并），水平扩散仍只进空气。
3. **`_hash01` 返回 float**，`& 3` 直接 TypeError —— 先乘 4 取整再截断。
4. **`disturb` 只激活空气邻格** ⇒ 源在水面、下方是海底地形，永远激活不到
   ⇒ 改"往上多看两格 + 只激活真正的水/源"。
5. **`fluid_step()` 不传 dt** ⇒ 计时器永远是 0、水流在正式路径永不跑；
   且 `getattr(self,'_fluid_t',0.0)` 拿到过 `None` 而报 TypeError。现在
   `__init__` 显式初始化 + `_post_step` 传真实 dt。
6. **粒子表 `resize(n)` 要的是顶点数**（线段数 ×2）⇒ 否则
   `Invalid data size: Expected 960, got 1920`。
7. **粒子必须关深度测试**（同 HUD）：粒子在 NDC 的 z=0，开着深度测试时
   **只有天空区域的雨线可见**（实测满屏只看见 2~3 条）。
8. **粒子 y 的初相位要按序号均匀铺满周期**（`i/n × SPAN`），
   只靠 `phase × 常数` 会让 320 条线挤成几团"锯齿粗线"。

## 十三、第二批不做（刻意）

* **水不会横向铺开成水面**：这是"垂直灌注"模型的直接代价（见 §九）。
  想要 MC 那种"倒水成池"需要先解决"CA 不收敛"，属后续批次；
* 水**不摧毁**方块（不淹没草/花）—— "淹没"在本项目没有玩法配套（没有水桶）；
* 水流声、雨声、闪电、雷暴：表现层留后续；
* 雨水**不会**让水位上升、不会淹洞（只有玩家挖穿才进水）。
