# Phase 2-C 设计稿（第一批）：洞穴 + 矿脉分层

> 范围：**洞穴空腔 + 自然洞口 + 矿脉按深度分层**（水流动 / 天气 / 村庄不在本批）。
> 这份稿的重点有两个：一是**三级洞穴场**为什么要预计算 + 块级剪枝（实测数据），
> 二是**加洞穴把 Phase 2-A 的光照引擎顶出一个阻塞级 bug** —— 那一节是本稿最有用的部分。

## 一、三个模块 + 内核挂点

| 模块 | 职责 | 关键取舍 |
| --- | --- | --- |
| `caves.py`（新） | `CaveField` 三级洞穴场 + `TunnelIndex` worm 隧道 + 三条护栏 | **预计算 + 块级剪枝**（§三）；不逐格做 3D fBm |
| `world.py` | `_column_block` 接入洞穴（矿脉之前）；`ORE_BANDS` 按深度分层 | 约束写在判据里，不靠调用顺序（沿用 Phase 0 的纪律） |
| `blocks/items/recipes/textures` | 金/钻石矿石 + 材料 + 掉落 + 程序化贴图 | **id 只追加**（矿石 20/21、材料追加在 `_defs()` 末尾） |

## 二、洞穴模型：cheese 空腔 + worm 隧道

| 手段 | 做什么 | 为什么 |
| --- | --- | --- |
| **cheese 空腔** | 三级噪声场超阈值就挖空 | "大空腔 + 块状边界"，与方块世界气质一致 |
| **worm 隧道** | 从地下向上游走的管状通道（球半径 1.9），**只在到达洞顶层时补一个"地表窗口"球** | 噪声挖穿地表是随机的、玩家找不到；worm 保证**必有洞口且位置可复现** |

护栏（三条，写在判据里）：**基岩与 y=1 不挖** / **表土保底 3 格**（洞顶有岩层）/
**水下地形整列不挖**（本项目没有流体系统，洞里进水没法修）。
worm 是唯一允许打穿表土的东西，但它也遵守"水下地形不挖"。

## 三、性能：为什么要三级场 + 块级剪枝（实测）

预算：默认世界 256×256×64，地下候选带 **1.83M 格**（实测平均 28 格/列）。

| # | 做法 | 实测 | 根因 |
| --- | --- | --- | --- |
| 1 | 逐格一次三线性插值的 3D 值噪声 | **+3.3s（4.82→8.11s，+68%）** | 每格 8 次哈希 + 8 次数组索引 + 插值 |
| 2 | 改成"预建 `CaveField` 实例，消掉每格的模块导入" | **8.11→8.10s，一分钱没省** | ⚠ **猜测错了**：真正的开销是每格的哈希与插值，不是导入 |
| 3 | cProfile 定位 | `_hash01` **187 万次**占 tottime **1.9s**；`is_cave` **2.65µs/次** ⇒ 全图 **+4.85s** | 实锤 |
| 4 | **三级场（粗格 8×4×8 / 块级中频 / 逐格细噪）+ 块级剪枝** | 剪枝率 **70~79%**；`is_cave` **0.75µs**；`generate()` **5.79s（+20%）** | 粗格离阈值太远的整块 256 格**连细哈希都不算** |

最终口径：阈值 **0.75 − 0.03×(1−y/sea)**（越深越低 ⇒ 越深越密），
64 高世界实测挖空 **10.0%**（浅层档最少、中层最多，方向正确）。

⚠ **别改 `_hash01` 的算法**：存档只存「种子 + 编辑增量」，地形/矿脉/洞穴
全部由它重算 —— 改哈希会让老存档里的玩家建筑浮空或埋进石头。
只能做**行为等价**的优化（把函数体内的 `import math` 提到模块级）。

## 四、矿脉分层（2-C 点名的另一半）

`ORE_BANDS = (煤 40 / 铁 28 / 金 16 / 钻石 8)`，深度上限**随世界高度等比缩放**
（基准 64 高）—— 与 `surface_height`/`sea_level` 同一套缩放纪律，写死绝对值会让
32 高的测试世界里钻石层挤成 3 格。

两条实现要点，都踩过：

1. **深度只决定"能不能出现"，同深度内各矿种按概率分段**。
   初版写成"从上往下第一个满足上限的带胜出" ⇒ y=27 永远只能是煤，
   铁实际只落在 y<16 —— **分层名存实亡**。改后（64 高实测）：
   煤 94383 > 铁 64899 > 金 18261 > 钻石 3437 ✓ 单调递减。
2. **一次哈希定矿种**（把 `[0,1)` 按各带概率切段），不是每带一次哈希：
   深层格平均 2.64 个候选带 ⇒ 初版 118 万次哈希；改后每格 1 次
   （`generate()` 从 8.1s 回到 5.9s）。

图集：加两张矿石贴图 ⇒ `ATLAS_COLS` 5→**6**（第 6 行会落到图集外面，
这是 `ATLAS_SIZE = ATLAS_COLS × TILE` 正方形假设的必然要求）。

## 五、加洞穴顶出来的**阻塞级 bug**（本批最重要的一节）

### 光照 BFS 没有盒子边界 ⇒ demo 直接起不来

症状：`python examples/mcclone3d.py --smoke 3` 抛
`LightOverflow: 光照扩散超出上限（sky）：已访问 1137538 格 > 400000`。

根因：`_spread_from` 的 BFS 用 `world_get` 扩散时**没有范围限制**。
世界没有洞穴时无所谓（地下全实心，扩散几步就撞墙停）；**一旦有洞穴**，
天光顺着洞口灌进整个洞穴系统 —— 每写一次值就再扩散一轮，访问量冲到 113 万，
而且它还是**错的**：洞里被灌成 level 14 的"全亮"。

修法（按 `relight_chunk` 文档早就写着的"只在本区块内扩散"补上实现）：
`_spread_from` 增加 `box` 参数，`relight_chunk` / `relight_around` 都传盒。
修后：全图逐区块 relight 通过；洞内黑 4231 / 亮 1645（亮的只在洞口附近，正确）。

## 六、其余实测踩坑（都留了判据）

1. **`COARSE` 的尺度被当成插值权重**：`c + (c1-c)*8` 把 density 值域放大到
   ±316 ⇒ 阈值从 0.585 调到 0.75 挖空比例都是 49.5%（怎么调都没用）。
   正确：粗格场只存**纯节点值**，插值统一在查询时做。
2. **阈值方向写反**：写成 `+0.02×(sea-y)/sea` ⇒ 深处阈值 0.679 > 浅处 0.660，
   实际成了"越浅越密"。单测 `t_threshold_deeper_denser` 抓到的。
3. **worm 的球打不穿地表**：半径 1.9 的球在**整数格**判定下只到 ±1 格
   （`dy=2` 时距离²=4 > 3.61），球心停在"离地表 3 格"就够不到地表格。
   修法：到达洞顶层时**额外补一个球心在 `h-1` 的球**，正好覆盖 `h-2/h-1/h`
   —— 表土保底 3 格与"打穿地表"两件事同时成立。
4. **`is_cave` 重构时丢了一条护栏**：重构把"水下地形整列不挖"弄丢了，
   于是岸边地形（h ≤ sea+1）下面被挖空。单测 `t_underwater_column_untouched` 抓到。
5. **洞口的"可达"判据一度用海平面挡天空**：洞口在 y≈34 而海平面只有 30，
   用 `sea` 会把洞口那几层一起挡掉 ⇒ 明明连通的隧道被判成不可达。
   正确：按**该列自己的地表高度**挡天空。

## 八、不做（这一批刻意不碰）

* **水流动**：没有流体系统之前，洞穴不能进水（三条护栏之一就是为此）；
* 洞穴不与水面连通（想看"水底洞"要等流体）；
* 熔岩/岩浆层、洞内藤蔓、洞穴生物变种：留给 2-C 后续或 Phase 3；
* 洞顶塌方（方块掉落物理）：Phase 3。
