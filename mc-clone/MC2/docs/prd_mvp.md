# PRD：我的世界复刻版（2D 文字向）· 可玩 MVP

> 产品经理：许清楚（Xu）
> 范围：仅需求分析，不写代码、不修改任何源码。
> 方向：2D 侧视（Terraria 式）方块世界，文字(ASCII/ANSI)渲染，绝不引入 3D。

---

## 0. 项目信息

- **语言**：中文
- **技术栈**：Python 3.14 + 纯净引擎 `allin_engine`（`core/ecs`、`core/event_bus`、`core/game_loop`、`systems/input`、`systems/inventory`）+ 第一轮 mc_clone 地基（`geometry` / `noise` / `block_registry` / `block_world` / `terrain` / `text_world_renderer` / `input_realtime`）；pygame 为可选软依赖（仅用于捕获键盘）；渲染为 ANSI/ASCII 文本。
- **项目名**：`mc_clone_mvp`
- **原始需求复述**：在第一轮「引擎地基」之上，交付一个可玩 MVP——2D 侧视文字方块世界，玩家可左右移动、跳跃、受重力并碰撞；可破坏/放置方块；相机（文字视口）跟随玩家；由引擎 `FixedTimestepLoop` 驱动、每帧读 `RealtimeInputManager` 按键并更新世界，关键行为通过 `EventBus` 发预置 `EventTypes`。

---

## 1. 产品目标

> 本 MVP 让玩家在确定性生成的 2D 侧视文字方块世界中，用键盘控制角色移动、跳跃、受重力并与地形碰撞，能破坏与放置方块，并借由始终跟随自己的文字视口实时观察与改造世界。

---

## 2. 产品目标拆解（3 个互斥正交目标）

1. **可玩闭环**：实现稳定的「移动 + 重力 + 碰撞」角色控制，玩家能真正走、跳、落地、站住。
2. **可塑世界**：玩家可破坏/放置方块，世界状态发生改变且可被渲染观测。
3. **流畅可扩展骨架**：以固定步长循环 + 跟随相机 + 事件总线，提供持续实时体验，并为后续玩法（生存、合成、存档）预留接入点。

## 4. 需求池（P0 / P1 / P2）

> 优先级含义：P0=必须（MVP 可玩底线）；P1=应有（体验完整）；P2=可选（占位/后续）。

### P0 — 可玩底线

| 编号 | 功能 | 验收标准 | 优先级 |
|---|---|---|---|
| R1 | **移动 + 重力 + 碰撞**：角色以 AABB 与 `BlockWorld` 做碰撞；左右移动、跳跃初速度、重力下落、落地静止 | ① 角色不能进入 `solid` 方块内部；② 站在 solid 上方时 y 稳定不再下落；③ 水平撞墙被阻挡；④ 跳跃可达约 3–4 格高并落回地面 | P0 |
| R2 | **破坏方块**：选定目标方块并将其设为 air | ① 目标格变为 0；② 世界 `to_dict()` 改变；③ 不能破坏角色脚下站立格导致穿地（边界保护） | P0 |
| R3 | **放置方块**：在角色相邻空位放置手持方块 | ① 目标格变为手持方块 id；② 不可放置在角色 AABB 占用格（防卡死）；③ air/水格可被覆盖 | P0 |
| R4 | **相机跟随**：视口（`AABB2D`）以玩家坐标为中心、尺寸固定，复用 `TextWorldRenderer` 渲染 | ① 玩家移动时视口随动且玩家居中（或接近居中）；② 抵达世界边界时视口钳制到世界 `bounds()` | P0 |
| R5 | **游戏循环**：用 `FixedTimestepLoop` 驱动 `update(读输入→更新玩家→发事件)` + `render(文字渲染)` | ① 每帧从 `RealtimeInputManager` 读按键；② 逻辑固定步长、渲染解耦；③ 渲染输出刷新可见 | P0 |
| R6 | **事件触发**：移动/破坏/放置/落地经 `EventBus` 发预置 `EventTypes` | ① `PLAYER_MOVED` 携带位置与朝向；② 破坏/放置分别发对应事件并携带方块 id/坐标；③ 订阅者可接收；④ 缺失专用预设（见注释）需补 `BLOCK_BROKEN`/`BLOCK_PLACED`/`PLAYER_LANDED` 或复用 `ITEM_TAKE`/`STATION_PLACED` | P0 |

> **事件映射建议**：移动 → `PLAYER_MOVED`；破坏 → 新增 `BLOCK_BROKEN`（或暂复用 `ITEM_TAKE`）；放置 → 新增 `BLOCK_PLACED`（或暂复用 `STATION_PLACED`）；落地 → 新增 `PLAYER_LANDED` 或在 `PLAYER_MOVED` 数据加 `on_ground` 标志。建议本轮直接给引擎 `EventTypes` 补 3 个方块相关常量，避免语义扭曲。

### P1 — 体验完整

| 编号 | 功能 | 验收标准 | 优先级 |
|---|---|---|---|
| R7 | **HUD**：在视口外显示玩家坐标、手持方块、FPS/种子 | ① HUD 实时随状态更新；② 不破坏世界网格对齐 | P1 |
| R8 | **手持/库存切换**：复用 `systems/inventory.py` 或固定手持循环（见待确认④）；数字键/滚轮切换手持方块 | ① 切换后放置使用新方块；② HUD 显示当前手持 | P1 |
| R9 | **目标高亮（准星）**：在文字渲染中高亮当前指向的目标方块 | ① 目标格有可辨识视觉区分（颜色/标记）；② 随瞄准移动 | P1 |

### P2 — 占位/后续

| 编号 | 功能 | 验收标准 | 优先级 |
|---|---|---|---|
| R10 | **音效占位**：预留破坏/放置/跳跃触发点，MVP 仅日志/空函数 | ① 调用点存在，可被后续替换为真实音效 | P2 |
| R11 | **存档**：复用 `BlockWorld.to_dict`/序列化 + 引擎 `save_load` 保存/加载世界与玩家状态 | ① 重载后世界与玩家一致 | P2 |
| R12 | **死亡/重生占位**：复用 `PLAYER_DIED`/`PLAYER_RESPAWNED`，预留坠空/溺水判定 | ① 事件可触发可订阅（MVP 仅占位） | P2 |

## 5. UI / 交互设计稿

### 5.1 终端布局（ASCII 草图，视口以玩家 `@` 为中心跟随）

```
+--------------------------------------------------+  ↑ 顶部 HUD（1 行，R7）
| XY:(32,11) 手持:stone(#) x64  FPS:60  种子:12345 |
+--------------------------------------------------+
|                  .#####.                         |  ↑ 世界视口（文字渲染，跟随玩家）
|                  .""""".                         |    普通方块按 glyph+color 绘制
|             @    .#####.                         |    @ = 玩家（叠加在对应格）
|            #### .#####.                          |    [ ] = 当前指向目标高亮（R9）
|            ####[~]~~~~~                          |
|            ####:####:                           |
|                                                  |
+--------------------------------------------------+
| A/D 移动 · Space/W 跳 · 左键破坏 · 右键放置 · 1-6 切换 · Q 退出 |  ↑ 底部提示条（可选）
+--------------------------------------------------+
```

说明：
- 世界视口复用 `TextWorldRenderer.render(world, viewport)` 产出字符网格；玩家与其 AABB 在渲染前以 `@` 叠加到对应格（渲染层叠加，不改 `BlockWorld` 数据）。
- 视口尺寸固定（见待确认⑤），玩家在视口内居中；世界边界处钳制。
- HUD 与提示条不计入视口字符网格，避免与世界对齐冲突。

### 5.2 键位映射（初稿，待确认③）

| 操作 | 建议键位 |
|---|---|
| 向左移动 | `A` / `←` |
| 向右移动 | `D` / `→` |
| 跳跃 | `Space` / `W` / `↑` |
| 破坏指向方块 | 鼠标左键 / `J`（方案见待确认②） |
| 放置手持方块 | 鼠标右键 / `K` |
| 切换手持方块 | 数字 `1-6` / 鼠标滚轮（若采用库存方案 R8） |
| 退出（停循环） | `Esc` / `Q` |

> 输入统一经 `RealtimeInputManager.is_down()` / `pressed_this_frame()` 读取，避免每帧重复触发（如跳跃用「本帧刚按下」）。

## 6. 待确认问题（必列，且具体化）

- **① 运行载体（渲染宿主）**
  - 方案 A：纯 ANSI 终端输出——pygame 仅作键盘捕获、需一个最小隐藏窗口（`pygame.display.set_mode` 不可见或 1×1）；世界以 ANSI 彩色字符 print 到终端。优点：零额外渲染层、最贴近第一轮 `main.py` 风格。缺点：逐帧清屏/重绘在部分终端有闪烁。
  - 方案 B：在 pygame 窗口内用字体（如 `pygame.font`/位图字体）绘制文字世界。优点：可控重绘、无终端闪烁、易做 HUD/高亮。缺点：偏离「纯文本」、需处理字体与字符宽高。
  - **需主理人/架构师决策**：MVP 用 A 还是 B？

- **② 破坏/放置的目标选择方案**
  - 方案 a：准星指向——玩家面朝方向 + 视线距离内最近方块（Terraria 式）。
  - 方案 b：玩家正前方相邻方块——固定取面朝方向紧邻一格（最确定、最简单）。
  - 方案 c：坐标/列表输入——文本输入目标格（偏命令式，实时性差）。
  - **需决策**：采用 a / b / c？影响 `input_realtime` 是否需要鼠标坐标或仅方向键。

- **③ 控制键位方案**
  - 初稿见 5.2（A/D + Space/W + 鼠标左右键 / 备用 J/K）。
  - **需确认**：跳跃是否同时支持 `W` 与 `↑`？破坏/放置是否必须依赖鼠标（方案②若选 a 需鼠标坐标；选 b 可纯键盘）？是否保留 `Esc` 退出？

- **④ 库存系统 vs 固定手持**
  - 方案 A（库存）：复用引擎 `systems/inventory.py` 的 `Inventory`，破坏获得物品、放置消耗物品，数字键切换。更贴近 MC，但 MVP 需额外采集/消耗逻辑。
  - 方案 B（固定手持）：玩家循环持有几种方块（如 stone/dirt/grass/sand），`1-6` 直接切换，放置不消耗。实现最简、最快可玩。
  - **需决策**：MVP 走 A 还是 B？若 A，是否 MVP 仅做「切换+放置」不做采集消耗？

- **⑤ 视口/终端尺寸**
  - 候选：80×24（标准终端）、64×24（呼应第一轮 `main.py` 的 64×24 世界）、或更大如 100×30。
  - **需决策**：视口宽高（字符数）？是否等于生成世界尺寸还是小于世界（相机才有意义）？建议视口 < 世界尺寸（否则相机跟随无意义），例如世界 200×64、视口 80×24。
