## 2. 架构评估 (9/10) ⬆ +1

### 优势

- **清晰的分层结构**：`core/`（逻辑） → `data/`（数据加载） → `gui/`（界面），三层分离合理
- **数据驱动设计**：所有游戏内容（职业/技能/装备/怪物/地下城/事件）均为 JSON 配置，支持 Excel 覆盖，不修改代码即可调整游戏平衡
- **单例 DataLoader**：全局唯一的数据加载器，避免重复解析
- **打包路径适配**：`config.py` 正确区分 `frozen`（PyInstaller）和开发环境，JSON 内嵌、Excel 和存档放 exe 同目录
- ✅ **视图栈导航框架**：`gui/views/base.py` 定义了 `View` 抽象基类和 `ViewStack` 栈管理器，内置消息路由，为未来弹窗/子视图提供统一框架
- ✅ **Tick 驱动游戏循环**：`core/game_loop.py` 封装 `after()` 定时器，支持速度倍率(1×/2×/5×)和一键 `cancel_all()`
- ✅ **Mixin 模式拆分标签页**：5 个标签页各自为独立 Mixin 类（Tavern / Wilderness / Inn / Shop / Warehouse），app.py 仅负责编排，违反 SRP 的问题已解决

### 问题

- **GUI 与 Engine 耦合**：`gui/tabs/wilderness_tab.py` 仍直接操作 `engine.battle_log`、`engine.floor_buffs` 等内部状态，未通过接口
- **BattleSystem 是纯静态方法类**：没有利用 OOP，无法继承/扩展战斗规则
- **scenes.py 是废弃模块**：仅保留两个未使用的辅助函数 (23 行)，应清理

## 3. 代码质量评估 (7.5/10) ⬆ +0.5

### 优势

- **dataclass 模型**：10 个数据模型用 `@dataclass` 定义，清晰简洁
- **类型注解**：大部分函数有返回类型标注（`Optional[Tuple[ExploreEvent, str]]` 等）

## 4. 游戏平衡评估 (6.5/10) ⬆ +0.5

### 当前数值体系

| 参数 | 数值 | 评价 |
|------|------|------|
| 队伍上限 | 3 人 | 合理，限制了资源膨胀 |
| 初始金币 | 100G | 旅馆休息 20G/次，前期紧张感适中 |
| 经验公式 | `level * 100` | 前期升级快（Lv.2 = 100 EXP），后期慢 |
| 属性成长 | HP+12/级, ATK+3/级, DEF+2/级, SPD+1/级, MP+5/级 | HP 成长占比大，后期血牛倾向明显 |
| 技能上限 | 4 个 | 偏少，限制了战术深度 |
| 装备掉落 | 20% | 偏高，后期背包容易溢出 |
| 旅馆费用 | 20G（含复活） | 早期紧张，后期无感 |
| 地下城层数 | 5-10 层 | 体感适中 |

### 平衡问题

1. **没有死亡惩罚**：阵亡后只需旅馆 20G 即复活全队，无经验/金币损失，死亡压力几乎为零
2. **金币经济线性膨胀**：怪物金币 + 随机浮动（50%），但消费项只有旅馆（20G）、商店、刷新（10G），后期大量金币无处使用
3. **难度曲线断裂**：新手森林 diff=1 → 魔王城 diff=10，`scale = 1.0 + diff * 0.3`，后期怪物属性 4x 基础值，但角色成长只有 HP ~100 级差距，中期可能卡住
4. **扎营恢复太弱**：只恢复 20% HP + 15% MP，相比撤退回城（旅馆 100% 恢复+复活）性价比低，玩家永远选撤退
5. **技能系统 AI 太简单**：50% 概率用技能 + 按列表顺序遍历，没有优先级策略（如低血时优先治疗）

### QoL 改进
- ✅ **速度控制**：郊外设置区新增 1×/2×/5× 按钮，通过 GameLoop 实现，战斗和探索可加速

## 5. 可玩性评估 (7.5/10) ⬆ +0.5

### 亮点

- **暖色调纸卷风格 UI**：视觉辨识度高，脱离了 tkinter 默认的灰色丑陋感
- **系统托盘**：最小化到托盘后台运行，适合放置类游戏
- **叙事跑马灯**：底部轮播叙事文字，氛围感好
- **楼层间决策**：继续/撤退/扎营，给了玩家节奏控制权
- **事件系统**：5 种事件带多选项和概率判定，增加探索趣味
- **数据可编辑**：用户可修改 `game_data.xlsx` 自定义内容
- ✅ **批量速度控制**：一键切换游戏节奏，避免慢速战斗的等待疲劳

### 不足

- **交互深度不足**：战斗完全自动，玩家无法选择攻击目标或使用特定技能
- **长期目标缺失**：没有成就系统、通关奖励、新游戏+ 等循环动机
- **单一胜利条件**：打通 7 座地下城后无后续内容
- **角色个性化弱**：同名同职业同种族的角色完全相同，没有随机属性差异（骰子只在 UI 上有但未接入 `recruit()`）
- **仓库 UI 不够直观**：装备管理在仓库页逐角色逐槽位操作，不如 dialogs 装备弹窗方便

## 8. 总结

**探险日志是一个完成度良好且架构持续优化中的小型桌面放置 RPG**。经过本轮对标 pq2 的改造后：

- ✅ **架构提升**：app.py 从 1,529 行臃肿单文件精减至 450 行编排层，5 个标签页独立为 Mixin，职责清晰
- ✅ **基础设施**：新增 GameLoop（Tick 驱动 + 速度控制）和存档哈希（防篡改），为未来扩展打下基础
- ✅ **体验提升**：1×/2×/5× 速度控制让玩家按需调整游戏节奏
- 🆕 **潜在价值**：ViewStack 已就位但尚未充分接入，可作为弹窗/子视图的统一导航框架

**最紧迫的问题是 Skill CD 的共享实例 Bug**（P0），这会导致技能在多场战斗后永远冷却。其次是怪物技能未实现、事件奖励硬编码等 P1 问题。

**作为独立游戏项目**，当前 ~3,900 行代码 + 9 个 JSON 文件已经是一个功能完善的 MVP。如果要继续迭代，优先级建议：

1. 🔴 修复 Skill CD bug（P0，影响核心战斗体验）
2. ⚠️ 实现怪物技能系统（数据已有，逻辑缺失）
3. ⚠️ 接入 ViewStack 到弹窗场景（装备选择/事件决策）
4. ⚠️ 事件奖励从 loader 动态读取
5. 💡 增加死亡惩罚或难度选择
6. 💡 加入成就系统延长游玩寿命
